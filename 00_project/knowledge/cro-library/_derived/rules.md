# 741 CRO-Raster — Rules (derived from the CRO library)

Derived 2026-10-11 from 65 transcripts in `00_project/knowledge/cro-library/`. Internal document. Never name the sources in client material. Call it "741 CRO-Raster".

Format: IF situation THEN action. Why. Src = file numbers in the library. Where a source rule gives a healing promise, the rule here is already adapted to HWG (German health advertising law).

Status: approved by Martin 2026-10-11. Only the "Learnings" section changes per client.

**Industry mode:** rules marked (HWG) are the health version. For non-health clients use the original result-based wording when real data backs the claim. L8 and L9 apply to health clients only. L10 applies always.

## 0. Process rules

- R0.1 IF you plan the work THEN spend 80–90 % of the effort on the hero (above the fold). Why: 100 % see it, about 60 % never scroll past it. Src: 003, 015, 030, 043, 054
- R0.2 IF you start a page THEN write the copy first and design around it. Why: layout must serve the message. Src: 022, 034, 048
- R0.3 IF you plan sections THEN define each section's job (what the visitor should feel, think, do) before you design it. Src: 017
- R0.4 IF you need copy THEN take the words from reviews, first-call questions and messages. Why: customers already wrote the copy. Src: 002, 013, 027, 031, 045
- R0.5 IF the page is the homepage of a local practice THEN treat it like a landing page: it is an entry page from Google and Maps. Src: 006, 039, 048
- R0.6 IF traffic is under about 25,000 visits per month THEN skip A/B tests. Make the proven changes in one revamp and judge by recordings and contacts. Src: 009, 039, 051, 061
- R0.7 IF someone says "best practice" THEN treat it as a hypothesis for this audience, not a law. Src: 010, 027, 060

## 1. Hero (above the fold)

- R1.1 IF a visitor lands THEN the hero answers in 5 seconds: what is this, who is it for, what do I do next. Src: 001, 020, 031, 050
- R1.2 IF you build the hero THEN use this stack: benefit headline, sub-headline (pain → how you help, 3–4 specifics), two forms of proof, one primary CTA, reassurance line under the CTA, one real image. Src: 006, 022, 051, 062
- R1.3 IF the hero image appears THEN it shows the real practitioner, the real room or the felt outcome, never decoration or stock. Src: 009, 024, 028, 042, 064
- R1.4 IF the hero image shows a person THEN the person smiles, looks natural, and the gaze points to headline or CTA. Src: 021, 042
- R1.5 IF the hero has empty space, a tall header or a huge logo THEN compress it so headline, proof, CTA and reassurance fit in the first screen, also at 390 px. Src: 003, 024, 032, 051, 065
- R1.6 IF you compress the hero THEN leave a visible edge of the next section. Why: a full-screen hero signals "nothing more here". Src: 018
- R1.7 IF the hero has more than one offer or more than two buttons THEN cut to one primary action (plus phone/WhatsApp as the secondary path). Src: 011, 028, 029
- R1.8 IF the practice must rank for a keyword THEN keep the keyword in the H1 but style it small; the big visible line is the benefit headline. Src: 003, 048
- R1.9 IF the visitor came from an ad, a Maps listing or a search result THEN the hero repeats the promise that earned the click. Src: 001, 028, 042
- R1.10 IF the hero body text runs past 3 sentences THEN cut it to 2–3 sentences that hold the top 3–4 value props. Src: 028, 042, 063

## 2. Headlines and copy

- R2.1 IF you write the headline THEN state the outcome the visitor wants plus the emotional payoff. Never who you are or what you do. Src: 007, 022, 029, 043, 049
- R2.2 IF the headline formula asks for a time frame THEN use it only for service facts (reply time, appointment within X days). Never a healing time. Src: 003, 043 (adapted, HWG)
- R2.3 IF the headline is clever, a question or a buzzword THEN rewrite it clear and definite. Src: 006, 017, 046, 061
- R2.4 IF you write the sub-headline THEN name the pain first ("Du hast schon vieles probiert …"), then how you help with 3–4 specifics. Src: 011, 022, 051, 062
- R2.5 IF you need a headline angle THEN ask "so that" until you reach the deepest benefit (feel safe, be there for the family, move without fear). Src: 009, 033
- R2.6 IF a section heading is a label (Leistungen, Über mich, Bewertungen, FAQ) THEN rewrite it so the heading carries the claim. Src: 011, 030, 065
- R2.7 IF someone reads only the headings THEN the page still sells. Write every heading as a benefit. Src: 006, 021, 034, 043
- R2.8 IF copy says "wir" THEN rewrite to "du" and what the visitor gets. Src: 006, 017, 029
- R2.9 IF copy has jargon or long paragraphs THEN use plain words, 1–2 sentences per paragraph, bullets, bold key phrases, reading level of a 12-year-old. Src: 004, 014, 033, 049, 053
- R2.10 IF you can state a real number THEN use it (review count, years, patients per year, reply time). Numbers read as objective. Src: 006, 031, 062
- R2.11 IF the copy sounds like AI or marketing THEN rewrite it in the words patients use. Src: 013
- R2.12 IF you write value props THEN pair feature with benefit and put the benefit in the heading; 4–8 value props, the top 3–4 get their own section. Src: 003, 022, 034, 048, 051

## 3. CTA

- R3.1 IF you set the primary CTA THEN there is one obvious action, visible in a blur test, with the only strong accent colour on the page. Src: 004, 005, 016, 050
- R3.2 IF you write the CTA text THEN it states the next step and its benefit ("Jetzt per WhatsApp schreiben – Antwort heute"), not "Kontakt" or "Absenden". Src: 003, 023, 028, 051, 065
- R3.3 IF the CTA feels like a sales push THEN soften it ("Kurz schreiben", "Erstgespräch anfragen"). Src: 031
- R3.4 IF the page is long THEN repeat the CTA in every major section and in the closer. Src: 001, 027, 028, 065
- R3.5 IF the visitor scrolls on mobile THEN a sticky CTA (WhatsApp or phone) stays on screen. Top or bottom bar both work. Src: 012, 042, 051, 054
- R3.6 IF some visitors prefer calling THEN show the phone number next to the primary button, clickable. Src: 022, 042
- R3.7 IF you place a CTA THEN put a reassurance line directly under it: reply time, no obligation, hours, first-visit duration, what happens next. Src: 006, 023, 028, 043, 064
- R3.8 IF the CTA repeats THEN repeat the same check marks under each CTA. Src: 042
- R3.9 IF the CTA would open a separate contact page THEN open the chat or scroll to the on-page block instead. Exception: anxious audiences may prefer a calm contact page. Src: 001, 042
- R3.10 IF the first step is a calendar booking THEN offer a lighter first step (message, short form). Src: 028, 064
- R3.11 IF badges, bars or icons share the CTA colour THEN restyle them neutral. Src: 003, 035, 045
- R3.12 IF a text link acts as a CTA THEN make it a real button. Src: 051

## 4. Proof and trust

- R4.1 IF you build the hero THEN stack two forms of proof (Google rating + count, plus a handpicked quote or a number such as years or patients). Src: 003, 015, 028, 051, 065
- R4.2 IF the rating exists THEN it sits at the very top, before the headline or right beside it. Src: 028, 063
- R4.3 IF you show a review THEN add Google logo, real first name, photo if available, and a short scannable headline. Do not change the text. Src: 003, 015, 042, 053, 062
- R4.4 IF you show reviews THEN lay them out open, never in a carousel. Carousels get under 1–2 % engagement. Src: 003, 022, 030, 046
- R4.5 IF reviews are many THEN show the best 5–6 stacked on mobile with "mehr anzeigen". Src: 004, 042
- R4.6 IF you have few reviews THEN show 2–3 handpicked quotes and do not advertise the count. Src: 001, 031
- R4.7 IF reviews mention treatment results THEN pick the parts about experience: feeling understood, time taken, clear explanation, calm room. No healing claims. Src: 007, 066 (HWG)
- R4.8 IF you head the proof section THEN write the benefit ("Über 120 Menschen aus Berlin-Charlottenburg vertrauen …"), never "Bewertungen". Src: 011, 021, 034, 049
- R4.9 IF proof can be visual THEN use real photos of practitioner, room and entrance beside the quotes. Src: 009, 021, 029, 047
- R4.10 IF you place proof THEN use 3–4 proof blocks across the page, one after each major claim and one at the contact block. Src: 006, 011, 024, 043, 064
- R4.11 IF a claim appears THEN place a matching testimonial next to it. Src: 006, 048
- R4.12 IF a testimonial answers a known fear ("Ich hatte Angst, dass …") THEN use it near the CTA. Src: 005, 031
- R4.13 IF "bekannt aus" logos exist THEN add what the outlet said. Bare logos add little. Src: 001, 021, 030
- R4.14 IF the service is delivered by a person THEN add a practitioner section: photo, qualifications, years, why she does this work, one personal quote. Src: 012, 051, 063
- R4.15 IF the practice has a team THEN show the team in a grid of real photos. Src: 004, 034, 042

## 5. Section order and traffic

- R5.1 IF traffic is search or Maps (solution-aware) THEN order: hero → proof → situations → services → first visit → practitioner → reviews → FAQ → location → closer. Src: 003, 007, 022, 046, 064
- R5.2 IF traffic is cold (social ads) THEN put a pain section before the proof. Not the default for a practice homepage. Src: 017, 034, 065
- R5.3 IF the page is long THEN keep it long only while every section adds something new. Length does not kill conversion, bad structure does. Src: 010, 027, 046
- R5.4 IF you structure the page THEN alternate light and dark bands and let each section lead into the next like a sales talk. Src: 027, 042, 064
- R5.5 IF the page ends THEN finish with a closer that mirrors the hero: benefit headline, 3–5 check marks, proof, reassurance, CTA (and phone). Src: 012, 022, 028, 043, 064
- R5.6 IF a step-by-step exists THEN keep it to 3–4 steps with benefit headings, the last step is the felt outcome, each step with an image. Src: 009, 022, 051, 064
- R5.7 IF you show differentiators THEN use about 6 items or a comparison table (you vs. doing nothing vs. standard care), checked for HWG. Src: 006, 023

## 6. Situations, objections and FAQ

- R6.1 IF you open the section after the hero with pain THEN describe situations the visitor recognises ("Du wachst mit Nackenschmerzen auf …"), then the way out. Never diagnoses or cure claims. Src: 011, 021, 043, 049 (HWG)
- R6.2 IF you list pains THEN always attach the way out in the same section. Src: 049, 064
- R6.3 IF visitors hold a blocking belief ("bei mir hilft nichts mehr", "zu spät") THEN answer it with a section that shows people in the same situation. Src: 037
- R6.4 IF you write the FAQ THEN fill it with real objections: price, Krankenkasse, Dauer, Vorbereitung, Absage, Parken, "Was passiert beim ersten Termin". Price first. Src: 012, 027, 031, 051, 062
- R6.5 IF the visitor fears the first step THEN list the fears and answer each near the CTA. Src: 065
- R6.6 IF price or time looks like the objection THEN also answer the deeper doubt: "Wird mir das helfen?" and "Fühle ich mich dort gut aufgehoben?". Src: 042

## 7. Offer, risk reversal and price

- R7.1 IF there is no money-back guarantee THEN use another risk reducer: free first call, no obligation, transparent prices, what happens next. Src: 022
- R7.2 IF a guarantee or free first step exists THEN show it under the hero CTA and again at the next decision point. Src: 018, 051, 065
- R7.3 IF prices are shown THEN show them clearly with no hidden costs, after trust is built, not in the hero. Src: 002, 005, 052, 060
- R7.4 IF the practice offers more than 3 packages or entry options THEN cut to 3. Src: 005, 016, 035, 045, 060
- R7.5 IF you want urgency THEN use calm real facts ("Antwort heute", "Termin diese Woche"), never timers or fake scarcity. Src: 002, 017, 052
- R7.6 IF the price needs justification THEN list what is included and what happens behind the scenes. Src: 033
- R7.7 IF you speak about speed THEN quantify service speed (reply within 1 hour, appointment within 5 days), never healing speed. Src: 009, 042 (HWG)

## 8. Contact block and forms

- R8.1 IF a contact block exists THEN it has a benefit headline (not "Kontakt"), 3–4 bullets of what happens next, proof beside it, then the CTA or fields. Src: 006, 036, 046, 048, 065
- R8.2 IF a form is used THEN 4 fields or fewer, one "Name" field, single column, visible labels, required fields marked. Src: 001, 006, 016, 036, 051, 061
- R8.3 IF a field is not needed for the first reply THEN remove it, or say why you ask. Src: 016, 036, 052
- R8.4 IF the practice needs qualified contacts THEN keep one qualifying element (concern type) and say who the practice is not for. Src: 039, 042
- R8.5 IF the visitor has sent a message THEN tell them who replies and when. Src: 006, 042

## 9. Imagery and visual design

- R9.1 IF you choose images THEN use real photos of practitioner, room, entrance, and the felt outcome. No stock, no AI look. Src: 004, 024, 029, 042
- R9.2 IF text blocks list benefits THEN turn them into 4–6 icon + short line items. Src: 025, 035, 047, 063
- R9.3 IF you set typography THEN headline 3–4× body, headline 32–57 px, body at least 16 px (18 px on mobile), max 3 lines headline. Src: 005, 016, 042, 051
- R9.4 IF you set colours THEN max 3–4 colours (one dark, two light, one CTA accent), 2 fonts, 8-pt spacing. Body text not pure black. Src: 021, 042
- R9.5 IF the brand is calm or clinical THEN use about 12 px button radius, not pill buttons. Src: 042
- R9.6 IF everything is bold THEN reduce emphasis to headline and CTA only. Src: 027, 035
- R9.7 IF animation exists THEN remove autoplay and parallax; motion only to explain. Src: 004, 065
- R9.8 IF the design looks dated or cluttered THEN fix hierarchy first (size, weight, colour, white space), then content. Src: 010, 031, 033, 039
- R9.9 IF the layout feels creative THEN use the familiar pattern: headline, text, CTA below, image beside. Src: 030, 052, 065
- R9.10 IF decorative shapes exist THEN point them to the CTA or key content. Src: 004

## 10. Mobile

> Out of scope in the CRO homepage workflow, which is desktop only (Martin, 2026-10-11). Kept for the later mobile workflow. The same applies to R3.5 (sticky CTA) and L6 (sticky WhatsApp button).

- R10.1 IF you design THEN mobile first at 390 px with its own layout, not a shrunk desktop. Src: 006, 027, 042
- R10.2 IF the mobile hero loads THEN headline, one proof, CTA and reassurance fit in the first screen; image above the text. Src: 005, 007, 042, 063
- R10.3 IF text and menu are placed THEN left-aligned, F/Z reading pattern. Src: 006, 027
- R10.4 IF key proof or steps exist THEN show them open on mobile; carousels only for low-priority lists far down. Src: 030, 042, 054
- R10.5 IF tap targets exist THEN at least 44 px. Src: workflow standard
- R10.6 IF you QA THEN check on a real phone, not only in the inspector. Src: 042

## 11. Navigation and speed

- R11.1 IF the nav has many items THEN cut to 4–5, max 7; logo + CTA + phone in the header; rest to the footer. Src: 005, 016, 035, 051
- R11.2 IF non-clickable items look like buttons THEN restyle or make them clickable. Src: 038, 044
- R11.3 IF the page loads under about 8–10 s THEN do not trade design for milliseconds; fix only gross problems and heavy widgets. Src: 006, 027, 031, 052, 060

## 12. Measurement

- R12.1 IF the site goes live THEN install Microsoft Clarity (free) and watch scroll depth, click map and recordings, mobile first. Src: 019, 031, 051, 061
- R12.2 IF the hero CTA gets under 3 % of clicks THEN rework position, wording or contrast. Target 3–7 %. Src: 003, 038, 051
- R12.3 IF a key block is reached by under 30–40 % THEN move it up. Src: 020, 051, 061
- R12.4 IF a new patient books THEN ask "Was hätte dich fast davon abgehalten?". Src: 013, 032, 044, 061
- R12.5 IF you judge success THEN count qualified contacts and booked first visits, not raw clicks. Src: 017, 039, 042

## 13. Local healing adaptation (741 rules on top of the library)

- L1 IF the practice is local THEN the city or district appears in the hero headline or sub-headline and in the H1. Src: 048 + 741 local SEO standard
- L2 IF the practitioner is the product THEN her face appears in the hero or in section 2 at the latest, with name and qualification. Src: 042, 063
- L3 IF a visitor has never been there THEN a "Dein erster Termin" section shows 3–4 steps, duration and price range. Src: 009, 051, 064
- L4 IF the GBP has a rating THEN it is shown in the hero with the count, linked to the Google profile. Src: 028, 063
- L5 IF the visitor must find the practice THEN a location section shows map, address, parking, public transport, hours. Src: 741 local standard
- L6 IF the preferred channel is WhatsApp THEN every CTA opens `wa.me/<number>?text=<prefill>` with a section-specific prefilled message, and a sticky WhatsApp button exists on mobile. Phone is the secondary path. Src: workflow
- L7 IF the channel is phone or a booking form THEN the same rules apply to that channel. The channel is asked per client.
- L8 IF any copy promises healing, a cure, a result tied to a condition, a before/after, or uses fear THEN rewrite or remove it (HWG). Allowed: situations, experience, process, qualifications, service facts.
- L9 IF reviews are used THEN only experience content, with first name and Google source; no result claims (HWG).
- L10 IF a fact is not in `dataset.md` THEN it gets `[FEHLT]`. Nothing is invented.

## 14. Rules that do not transfer (reference only)

- Bundles, price anchoring, cart drawers, add-to-cart badges, product galleries, search bars, collection pages [ecom].
- Free trial, no credit card, dashboard screenshots, G2/Capterra proof, progressive demo forms [saas].
- Separate landing page per ad channel: not needed while the only traffic is search and Maps.
- Income tables, bonus stacks, course modules: info products only.

## 15. Numbers to use internally (never as client claims)

- 60 % never scroll past the hero; 100 % see it. 20 % read, 80 % scan. Opinion in 50 ms, stay-or-leave in 5 s.
- Carousels: 1–2 % engagement. Nav: diminishing returns above 7 items. Forms: 4 fields or fewer.
- CTA click-through target 3–7 %. Headline 3–4× body. Body 16 px desktop, 18 px mobile.
- Reported lifts in the library: hero tightening +60–108 %, reassurance under CTA +40–62 %, reviews with photo/name/source +60–80 %, hierarchy fix +64 %, option cut 5→3 +53 %, icons instead of text +23–33 %, CTA-to-on-page-form +220 %. All from other niches, no promise.
