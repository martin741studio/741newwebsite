# 002 Can an Army of Claude Haiku 5.5 Subagents Beat Opus 5.5?
Source: Dubibubi, 2026-10-09, https://www.youtube.com/watch?v=Ug3x37N6Z_E
Reliability: Medium. Practitioner test with three tasks. The creator sells a skill (/delegate) in a paid community. One run per test, so results are anecdotal.

## Rules (IF situation THEN action. Why.)
- R1 IF a job splits cleanly into independent pieces (for example hunting for bugs in separate parts of an app) THEN hand it to a team of Haiku subagents. In the code review test the team saved 61% of cost versus solo Opus.
- R2 IF a job needs taste or the full picture (for example a creative animation where everything must fit together) THEN let Opus work alone. In the film test the Haiku team cost nearly 80% more and took about an extra hour.
- R3 IF you want Opus to manage Haiku subagents THEN use a custom skill that defines Opus as manager and Haiku as executor. Asking for Haiku subagents inside the prompt made Opus cut corners and the handoff was messy.
- R4 IF Opus is manager THEN it does the thinking and planning and hands the building to Haiku subagents. Every handoff and check of the work costs tokens.
- R5 IF you compare setups THEN track input tokens, output tokens, time and cost per model on a usage dashboard. Haiku lost on cost early because it spawned many subagents and front-loaded token use.
- R6 IF you score code review THEN count confirmed bugs as +1 and made-up bugs as -1. This punishes hallucinated findings.
- R7 IF quality matters most THEN use Opus 5.5 solo. It won all three quality rounds in this test.

## Features and facts mentioned (with version or date if given)
- Haiku 5.5 costs 40 times less than Opus 5.5 (speaker's claim). Spend ratio: for every dollar Opus spends, Haiku spends 2.5 (as stated in the video).
- Both setups ran at extra high effort.
- Test 1, Angry Birds clone: solo Opus won on quality and time. Haiku won on cost. Haiku tokens were 91% of the lane's total, Opus 9%.
- Test 2, animated samurai short film in JavaScript (30 to 60 seconds): solo Opus won quality, speed and cost.
- Test 3, code review: Haiku team found 103 confirmed bugs, 14 rejected, score 89. Solo Opus found 122 confirmed, 0 made up. Opus finished about 10 minutes faster.
- Sonnet 5.5 solo scored 85 (87 bugs) in an earlier test. Another model scored around 21 bugs.
- Final score: 10 points to 2 for solo Opus 5.5.
- About 13 to 14 Haiku subagents ran at once. You can open each subagent transcript.
- Judge model for the bug reports: GPT6 Astra, named as the best code review model.

## Mistakes to avoid
- Do not assume a cheap-model army saves money. Handoff overhead can erase the saving.
- Do not rely on a plain prompt to make Opus delegate well.
- Do not trust unverified bug reports. Haiku made up 14.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- Parallel cheap workers suit batch tasks that split cleanly, such as auditing many pages one by one. Keep one strong model for writing that needs one voice.
- The video does not test non-code work. This is an inference, not a tested result.
