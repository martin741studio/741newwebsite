# 015 9 Claude Skills I Use Every Single Day
Source: Dubibubi, 2026-09-26, https://www.youtube.com/watch?v=LCwT00LrPZg
Reliability: Medium-low. Practitioner opinion list ranking third-party skills. HubSpot sponsors the video. The speaker tests creator claims and finds them lower. Skill names come from auto captions, so spelling is uncertain.

## Rules (IF situation THEN action. Why.)
- R1 IF Claude is wordy and burns tokens THEN try the caveman skill. It drops preamble. Creator claims 65% fewer tokens. The speaker measured about 35%.
- R2 IF you want to run parallel agents THEN make one agent rigorous first. Trust in output is the real problem, not parallelism. This is the idea behind pstack (skills from "Potato"): go deep first, then go fast.
- R3 IF you build apps with AI THEN run a security skill (Vibe Security) after every big update. It checks stack-specific issues (for example Supabase or Next.js). It found fatal problems in a shipped side project. Typical AI mistakes: hard-coded API keys, skipped security rules, letting the browser decide a price.
- R4 IF AI copy sounds like AI THEN run the "no AI slop" skill (by Peter Yang). It removes 22 AI writing patterns without flattening your voice, and lists every change so you can argue with it. Plain AI polish often removes the human parts (odd sentence length, bad analogies).
- R5 IF Claude writes too much code THEN try the ponytail skill. Claimed up to 94% less code. The speaker saw about 50%, with about 20% lower cost and 27% faster.
- R6 IF you want a base layer of skills THEN use Matt Pocock's skills (named "matte poke" in captions). Give the agent the repo link, start a long task, and say "use the skills where they make sense". Do not micromanage which skill fires. Skill descriptions are good enough for routing.
- R7 IF you want review inside an orchestration loop THEN have the orchestrator (Fable) delegate work to Sonnet models. Then use the code review skill so Sonnet reviews its own output before it returns to the orchestrator.
- R8 IF you need motion graphics THEN try the hyperframes skill. A firework animation took about 8 minutes. The speaker prefers it to Remotion.
- R9 IF you design UI THEN pair two skills: taste for a one-shot first design, and impeccable to audit consistency across many screens (spacing, grays, off-by-two-pixel buttons).
- R10 IF you want to optimize anything THEN use the autoresearch method: run hundreds of tiny experiments, keep what works, throw away what does not. Originally built to train AI models. You do not need the skill. Say "use the auto research skill methodology". Used on his app (many delight details) and on a gym plan. Running 100 experiments is not cheap. He used Opus 5 on medium effort.

## Features and facts mentioned (with version or date if given)
- Claim: over 500,000 Claude skills exist and most do not work (speaker's claim).
- Caveman has over half a million installs (as stated).
- Vibe Security has under 1,000 stars.
- Not in the top nine: unlazy (depth tree method against model laziness), AI job search, agent reach, open design (an open-source alternative to Claude Design that accepts skills).
- HubSpot's free guide "Claude at Work" maps Claude products, a model lineup and three workflows (sponsor content).

## Mistakes to avoid
- Do not run 8 parallel agents and hope. You cannot tell which one broke the app.
- Do not trust creators' savings claims without testing.
- Do not use AI to polish AI text without a skill that keeps your voice.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- No-AI-slop is directly useful for client copy and LinkedIn posts. The 741 workspace already lists a similar "slopmonster" skill, but the video does not mention it.
- Autoresearch method suits budget, thumbnails and landing page tests. The speaker says it works on anything. Cost can be high.
- Most other skills are for code or design.
