# 042 Anthropic Engineers Just Fixed Claude Code and Nobody's Talking About it
Source: Duncan Rogoff | Learn Claude Code, 2026-07-28, https://www.youtube.com/watch?v=UBFHTHUs1wA
Reliability: Medium. Practitioner reading the same Anthropic engineer article as extract 041 and demoing `/doctor`. Promotes his resources and another video.

## Rules (IF situation THEN action. Why.)
- R1. IF you use the newest Claude models (Opus 5, Sonnet 5, Fable 5) THEN revisit how you prompt. Anthropic removed over 80% of Claude Code's system prompt with no measurable loss in coding evaluations (per the article).
- R2. IF your context is large THEN know it is assembled from the system prompt, skills, global and project CLAUDE.md files, saved memory, and other sources you give it.
- R3. IF you want to right-size a setup THEN run `/doctor` in Claude Code. It is read-only first: it scans, reports, and asks before changing anything.
- R4. IF you run `/doctor` THEN it covers nine core areas: install health (duplicates, leftovers), broken settings files, broken or colliding agent definitions, dead weight (skills, MCP servers, plugins you never use, based on usage counters and session transcripts), CLAUDE.md repetition and redundancy, content Claude can work out itself (directory layout, tech stack, standard build commands), lazy loading, scripts that block the loop on every tool call, context weight, latest version, and permission fixes (auto mode as default).
- R5. IF CLAUDE.md holds things the session can discover (directory layout, tech stack, build commands) THEN remove them. CLAUDE.md loads every session and you pay each time.
- R6. IF you have always-loaded guidance THEN make CLAUDE.md a high-level index (like chapters or a glossary) that points to skills and subdirectory files. This is lazy loading.
- R7. IF guidance is only needed sometimes THEN put it in a skill. Example from Anthropic: they moved verification and code review out of the system prompt into skills that Claude calls only when needed (progressive disclosure).
- R8. IF you have many tools THEN use tool search with short definitions so Claude loads a tool only when needed.
- R9. IF you write rules THEN do not give 10 "don't do these" lines. Give judgment: say what you want to accomplish and let Claude pick the way. Conflicting instructions (such as "leave all documentation in" versus "add no documentation") cost extra work and are leftovers from older models.
- R10. IF you build a context tree THEN use a top-level CLAUDE.md or skill that says where to search, and sub-files for specific tasks. Do not make one central repository of every practice.

## Features and facts mentioned (with version or date if given)
- Article: "The New Rules of Context Engineering for Claude 5 models" by Thariq, Claude Code technical team.
- `/doctor` is described as a skill that ships with Claude Code. The speaker checked the desktop app and it did not appear to be available there; use the terminal.
- Claude Code now has memory, artifacts, and skills as ways to carry context across sessions.
- His result: install healthy and latest version; 113 personal skills use about 10,000 tokens of context per session just to list; 25 never used; the 88 personal skills were the bulk of token use (50 most recent sessions analyzed).

## Mistakes to avoid
- Cramming everything into one CLAUDE.md.
- Keeping skills and plugins you never use.
- Competing instructions across files.
- Letting `/doctor` change things without reading its report (it asks first; read it).

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- Same audit idea fits a growing skill library (many client and SEO skills): list, count unused, trim.
- Index-style CLAUDE.md pointing to client-specific files.
- Move verification and review steps into skills called only when needed.
