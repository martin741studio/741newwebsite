# 026 Insane Claude Design Skills You Need To Actually Build Beautiful Sites
Source: AI LABS, 2026-08-24, https://www.youtube.com/watch?v=Ysr7oNDajJI
Reliability: Medium. Practitioner list of third-party design skills. Sponsor read (Make, Maya) and sells a paid community (AI Labs Pro). Subjective quality claims.

## Rules (IF situation THEN action. Why.)
- R1. IF you want a site that does not look like every other AI site THEN add design skills. Each model has a design pattern that is easy to spot; skills steer it away.
- R2. IF you use skills in Claude Design THEN add them in Claude settings. The skills in your Claude setup are the same ones Claude Design uses. They also work in Claude Code and Codex.
- R3. IF you want to run a design skill THEN type `/` plus the skill name, then describe the site in the prompt. The skill asks questions first, then builds.
- R4. IF you start a design from scratch THEN begin with Emil Kowalski's design engineering skill (UI components plus animations). Then run his Animate skill to refine animations on the built site. The set has nine skills (includes an Apple design principles skill and an animation vocabulary skill).
- R5. IF the site is a landing page THEN expect scroll-based animation to matter most. Animate skill helps most on small functional elements (form submit, hover graphics), as in a restaurant site test.
- R6. IF you want a visually strong site THEN use Conor Lee's "web design engineer" skill (from a five-skill collection). It clarifies requirements, then looks for real designs to work from, with references for judging design and style recipes (Apple, Linear). On an existing design it scores it; rerun until the score is perfect.
- R7. IF the page has one job (get an action) THEN use a landing-page-specific skill (Elia Design AI design skill). It builds a visual system (colors, type, spacing) around one action and also covers search findability.
- R8. IF you want an award-style scroll-storytelling site THEN use Meng To's "Awards quality sites" skill. A "video to super prompt" skill in the same set turns a screen recording of a site into a prompt.
- R9. IF you want a design review THEN use Jakob Krehel's review skill, ideally connected to GitHub so it compares before and after and flags regressions. It checks animations, accessibility, and screen sizes. Use his better-layout skill for spacing and alignment (it reported extra pixels needed).
- R10. IF you want to avoid generic defaults THEN use the "tastemaker" skill. It extracts exact design details from the pixels of a reference image with scripts and saves them in a structured format, so detail is not lost in a text summary.
- R11. IF you want research-based critique THEN use a skill set built on named UX laws: screen critique (review across angles) and perception laws (how the eye reads a design). Install only the skills you need.

## Mistakes to avoid
- Trusting a long design workflow that still outputs a generic site.
- Using a homepage structure for a landing page.
- Relying on a text summary of a reference image (loses detail).

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- Landing-page skill and review/critique skills fit client prototypes (CRO homepage work).
- Review skill gives a score to iterate on before showing a client.
- Tastemaker approach: feed a client's reference image and keep exact style details.
