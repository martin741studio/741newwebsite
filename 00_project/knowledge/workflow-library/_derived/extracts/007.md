# 007 Anthropic Just Revealed 8 New Rules for Building Great Claude Skills
Source: Ben AI, 2026-10-06, https://www.youtube.com/watch?v=npS5jzOoji8
Reliability: Medium. Practitioner summarizing Anthropic's guides plus his own experience. He sells an AI accelerator course and a free skill-creator skill. He marks which tips are his own (multiple outputs, sub-agent rule).

## Rules (IF situation THEN action. Why.)
- R1 IF you want to automate a task THEN do it once with Claude first, then ask it to "turn this into a skill". Use the "turn into a skill" button in a chat. You give context and preferences while working, and people describe processes badly from memory.
- R2 IF the task is a screen workflow THEN use the "record a skill" feature. You do the task, explain what and why aloud, and Claude captures screen, clicks and voice, then builds the skill.
- R3 IF a skill covers many tasks THEN split it. Start with the smallest part that still gives value (for example research). Build separate skills for the rest and run them in the same chat. Focused skills compose better and keep context cleaner.
- R4 IF a skill misses edge cases THEN update it over time. Treat it as a living business process. The speaker iterates his best skills 5 to 10 times.
- R5 IF you test a skill THEN use one chat to build and refine it and a separate chat to test it on a real workflow. This keeps the test unbiased.
- R6 IF you hit edge cases often THEN add a self-improvement rule: every correction you give updates the skill file with a new rule.
- R7 IF output quality depends on style (design, copy, creative) THEN add input and output examples. Use at least 3 to 5. For copywriting, up to 20 can help. Examples show style better than descriptions.
- R8 IF you lack examples THEN add a rule: when I correct an output or like one, ask whether to save it as a permanent example in the skill.
- R9 IF a skill needs lots of context THEN use progressive disclosure. Put the process in SKILL.md and extra context in a reference folder. In each step name the reference files to read before that step. Do not load everything at the start.
- R10 IF a skill starts with research or connector calls (MCP, software data) THEN force a sub-agent for that step. It returns only a summary to the main agent. Add the rule "every connector call runs inside a sub agent".
- R11 IF a skill needs human review steps THEN make it give multiple variations at each checkpoint (for example several angles, then three outlines). This cuts iteration loops.
- R12 IF you want to run a skill only by slash command THEN set `disable-model-invocation: true` in the front matter. Claude cannot auto-trigger it. The skill description is then not loaded in every new chat, which keeps context cleaner.

## Features and facts mentioned (with version or date if given)
- Anthropic's engineering blog: progressive disclosure is the core design principle of skills. The amount of context bundled in a skill is effectively unbounded if done right.
- Anthropic says the context window is the fundamental constraint.
- Anthropic's best practices: keep skills small and focused. The most effective skill creators iterate on a single task before expanding.
- Anthropic blog: best skills began as a few lines and grew as Claude hit edge cases.
- Claude decides auto-triggering by reading the skill description.
- The speaker says Anthropic's skill-creator skill often does not apply progressive disclosure well.

## Mistakes to avoid
- Do not plan a skill into existence with a long prompt.
- Do not pack too many tasks into one skill. This is the most common mistake he sees.
- Do not read all reference files at the start. The agent forgets by the last step.
- Do not let a skill auto-trigger when you want manual control.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- Record-a-skill and turn-into-a-skill need no code. They suit repeat agency tasks (email triage, report writing, newsletters).
- Reference folders for ICP, voice and examples fit client deliverables: load the voice file only at the writing step.
- Multiple variations at human checkpoints fit copy and outline approval.
