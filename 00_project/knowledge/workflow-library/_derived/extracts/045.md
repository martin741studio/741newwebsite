# 045 Context engineering explained: What every AI developer should know
Source: Google Cloud Tech, 2026-07-15, https://www.youtube.com/watch?v=BBPQYtR7oUk
Reliability: Medium-high. Official Google Cloud channel, but it is not about Claude. The concepts apply to Claude workflows. The example is a toy agent ("log look"), not a tested product.

## Rules (IF situation THEN action. Why.)
- R1 IF an AI answer is bad THEN do not write a bigger prompt first. Fix what the model sees: decide exactly what it should see and not see at each step.
- R2 IF a context window fills up THEN expect lower accuracy, even with large windows. Errors creep in, and stale or irrelevant text distracts the model.
- R3 IF you debug an agent THEN name the failure mode. Four are listed: poisoning (a hallucinated fact is reused), distraction (the model fixates on long history), confusion (extra unrelated detail), clash (two sources disagree).
- R4 IF you build an agent THEN assemble seven context pieces: instructions, user input, retrieved facts, tools (with descriptions), short-term notes, long-term memory, output format.
- R5 IF instructions are written THEN use clear plain language. Add "only use provided context" and "if data is missing, ask for a specific file path".
- R6 IF the agent needs a format THEN lock it with a schema or example. The example uses JSON in and JSON out.
- R7 IF the agent must remember plans or results THEN WRITE them outside the context window (scratchpad, "investigation steps" list). Pull them back only when relevant.
- R8 IF you feed data THEN SELECT only what matters now. Example: only error or critical lines from the last hour, plus the false-positive list. Hybrid retrieval (keyword plus semantic) often beats embedding-only search on messy logs.
- R9 IF history grows long THEN COMPRESS. Keep the last five findings raw. Roll older ones into a three-line recap, then continue with a fresh window.
- R10 IF a job is big or sources are noisy THEN ISOLATE with subagents or phases. Each works in its own context and returns a short digest to a coordinator. Example: reader, scorer, writer.
- R11 IF in doubt THEN curate. Do not dump large prompts.

## Features and facts mentioned (with version or date if given)
- Prompt engineering = how you word instructions, examples, constraints. Context engineering = everything the model sees at runtime. It is dynamic and happens before every model call.
- The speaker names four steps: write, select, compress, isolate. (The spoken intro says "select, compress and isolate"; the list has four items.)
- Example agent "log look" triages Azure security alerts. It outputs a one-paragraph summary plus a severity score from 0 to 4.

## Mistakes to avoid
- Padding prompts like an essay to get better answers.
- Hoarding retrieved text instead of selecting it.
- Dragging a full raw chat history into every call.
- Letting one noisy source feed all steps.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- Apply "select": give a client-page task only that client's data (keywords, NAP, brand notes), not the whole project folder.
- Apply "isolate": split a deliverable into research, scoring, and writing steps with short handoffs.
- Apply "write": keep a running notes file per client task instead of a long chat.
