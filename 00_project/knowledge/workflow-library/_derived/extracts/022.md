# 022 Anthropic Just Revealed 7 New Rules for Prompting Claude 5 Models
Source: Ben AI, 2026-09-02, https://www.youtube.com/watch?v=HDmBwU5uvEE
Reliability: Medium. Practitioner summarizing Anthropic prompting guides and a Boris Cherny keynote (Y Combinator). Sells an AI accelerator course and free resources.

## Rules (IF situation THEN action. Why.)
- R1. IF you give a Claude 5 model a complex task THEN give the whole job up front, not step by step. The models are trained for end-to-end tasks (per the Anthropic Opus 5 and Fable 5 prompting guides).
- R2. IF you prompt THEN use four parts: the job, the why, the guardrails, and what done looks like. Boris Cherny: describe the task, guardrails, and exit criteria, then let the model run.
- R3. IF you do not give exact steps THEN do not write "do one, then two, then three". Over-specific step orders are a common mistake with modern models.
- R4. IF the task is complex and you are unsure of the details THEN run an "interview me" skill first. It asks questions and then writes a brief (job, why, guardrails, done) to paste into the model. Anthropic uses this internally, per the speaker.
- R5. IF you want to give context fast THEN dictate by voice (Wispr Flow or Claude's built-in voice tool). Then structure the rambling with a prompt-organizing skill, because messy input is also bad for the model.
- R6. IF you write the request THEN state why it is needed. Template: "I'm working on [larger task] for [who it is for]. They need [what the output enables]. With that in mind, [request]." The model makes better small decisions.
- R7. IF the model runs too long or spends many tokens THEN define exit criteria and output style (for example "8 to 15 tips, one example each, with source").
- R8. IF you want a specific output format THEN add an example of that format. The speaker says examples still help.
- R9. IF you write guardrails THEN give a reason instead of "never do X". Example: "make sure points are backed by Anthropic's own team, so we have proof" instead of "never give a point not backed up".
- R10. IF your CLAUDE.md or skill files have hard rules THEN rewrite them with reasons. Anthropic released a "rule rewriter" skill for this.
- R11. IF you use Claude 5 models THEN do not add "double-check your work" or a verification subagent just for that. The models verify and fix mistakes by themselves; the extra step adds cost.
- R12. IF you write prompts THEN avoid "think step by step", "explain your reasoning", and ALL CAPS emphasis. Anthropic recommends avoiding them; caps can cause over-triggering.
- R13. IF Opus 5 output is jargon-heavy or too long THEN add a short voice instruction to CLAUDE.md, Claude desktop global instructions, or a project system prompt (for example "keep responses focused, brief, concise, avoid jargon").

## Mistakes to avoid
- Prompting step by step and iterating on outputs.
- Giving only what to do, not why.
- Leaving out the "done" definition (model keeps going).
- Hard "never" rules without a reason.
- Asking the model to double-check.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- The job/why/guardrails/done frame fits client deliverables (page spec, audit, outreach batch).
- Put audience and purpose into every prompt ("for a local practice owner, needs to rank in Maps").
- Rewrite existing CLAUDE.md and skill rules to include reasons.
- Use voice dictation plus an organizing skill for briefs.
