# 018 Anthropic Engineer Explains: What to Build Instead of AI Agents
Source: Nate Herk | AI Automation, 2026-09-13, https://www.youtube.com/watch?v=HIRDzMtuWFk
Reliability: Medium. Practitioner summarizing remarks by two Anthropic engineers (creators of agent skills) with his own examples. Sells a course and communities. The title overstates: Anthropic did not say agents are dead.

## Rules (IF situation THEN action. Why.)
- R1 IF you want help with a new job (presentation, company research, LinkedIn post) THEN give a general-purpose agent a skill for that job. Do not build a separate agent for each job. Analogy: model = processor, agent runtime = operating system, skills = apps. A skill holds the process, context, scripts and examples.
- R2 IF Claude writes the same script again and again THEN save the proven script in the skill's scripts folder. Anthropic's team saw Claude rewrite the same Python script to style slides each time, which wasted tokens and gave different results. This is DRY: don't repeat yourself.
- R3 IF Claude wrote a script you like THEN say: save the script you just used in the skill's scripts folder, update SKILL.md so future runs execute that file, then run the skill again and verify the result. Then run the same task twice and check the skill calls the saved file.
- R4 IF you build many skills THEN write each description clearly. At startup Claude reads only name and description (the YAML front matter). It reads the full SKILL.md when a prompt matches. Scripts and references stay in the folder until needed (progressive disclosure).
- R5 IF two descriptions overlap ("help with content" and "create marketing assets") THEN Claude guesses. Write what the skill does and when to use it, with words a real person would use. Example: "creates LinkedIn carousels from a topic, transcript or outline. Use when the user asks for a carousel, carousel slides or a LinkedIn document post." Keep each skill to one job.
- R6 IF you want to audit descriptions THEN ask Claude Code to review all of them: what each does, when it triggers, where it overlaps, and rewrite only ambiguous ones. Test three requests: an obvious one, a differently worded one that should trigger, and an unrelated one that should not.
- R7 IF you correct Claude THEN do not just say "fix it". Ask it to review what went wrong, decide the cause (process, missing context, weak rule, unreliable code), update the skill in the smallest durable place, rerun and verify. Process wrong: edit SKILL.md. Missing voice, brand or examples: add a reference file. Repeated mistake: add an explicit rule.
- R8 IF an agent cannot find a file THEN ask it to show where it searched and why it missed, and update the routing or skill.
- R9 IF a skill produces a first draft THEN build verification into it. Before returning, define acceptance criteria, create the first version, inspect it with a method, fix issues, run another pass, and return a short summary of what was checked and what could not be verified.
- R10 IF output is a slide deck THEN render each slide as an image, inspect the screenshots, fix cropped or unreadable parts and re-render. IF it is a research report THEN open primary sources, match claims to evidence and remove what cannot be verified. IF it is a script or ad THEN use sub-agent personas (beginner, skeptical buyer, audience member), keep issues that repeat, revise, review again.
- R11 IF you want an agent-independent skill THEN test an important skill with another compatible agent. If it falls apart, look for hidden assumptions or missing examples. Agent skills are an open format.

## Features and facts mentioned (with version or date if given)
- The two engineers named in captions as "Barry Jien" and "Mahesh Marog" (spelling uncertain) created agent skills at Anthropic.
- Skills store procedural knowledge, not a record of every conversation.
- "Model proof" is not guaranteed: a weaker model will not match a stronger one.
- Speaker's AI OS is organized around agents, context, connections, capabilities and cadence (he lists these in the outro).

## Mistakes to avoid
- Do not pay Claude to rediscover a solution you already have.
- Do not let Claude mark its own work "looks good". Use evidence outside the first draft (screenshot, test, source).
- Do not accept all persona feedback. It can make output worse.
- Do not let two skills compete for the same request.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- Saved scripts and templates fit repeatable client deliverables (carousel, report, deck). Claude only changes the text.
- Verification patterns (render and inspect, source check, persona review) fit client reports and copy.
- Skill description audit applies to a growing agency skill library.
