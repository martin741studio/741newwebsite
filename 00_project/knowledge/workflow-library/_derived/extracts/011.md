# 011 You Need To Add This In Your Claude Code Setup Right Now
Source: AI LABS, 2026-10-05, https://www.youtube.com/watch?v=i6Q7bXnWGlM
Reliability: Medium. Practitioner tour of settings and commands. Has a sponsor segment (Scribba) and promotes AIABS Pro. Captions garble many setting names, so exact spelling needs checking before use.

## Rules (IF situation THEN action. Why.)
- R1 IF /init fills CLAUDE.md with things Claude can learn by reading code THEN set a setting called "claude code new init" to 1 in the terminal before the `claude` command. /init then asks how you work (improve or start fresh, skills and hooks, Git use, how you deploy), shows a plan, and writes after you approve. CLAUDE.md should hold only what the agent must remember all the time.
- R2 IF you used another agent (Codex, Cursor) THEN run the import command with that agent's name. It lists instruction files and MCPs, lets you choose, builds a skill that copies them, and applies it.
- R3 IF your setup is old THEN run `claude api` with `prompt audit`. It uses sub-agents to check your setup and reports problems and fixes. Run it most right after a new model release.
- R4 IF you want to find unused skills THEN run skill doctor. It shows how often and when each skill was used and its token cost. Then ask Claude to delete unused ones. The skills command lists skills, and pressing T sorts by token count.
- R5 IF auto mode does not match your habits THEN run auto mode setup. It reads your project and session history, proposes new rules, and updates after you approve.
- R6 IF you want fewer prompts without changing auto mode THEN run fewer permission prompts. It finds your most used read-only commands in past sessions and adds them to an allow list in the project settings file.
- R7 IF connectors you never use (Notion, Slack) load into every session THEN set the disable claude AI connectors setting to true in settings.json in the main .claude folder. You can just ask Claude to add it.
- R8 IF you do not need artifacts THEN set the enable artifact setting to false. The tool loads into every session and uses context.
- R9 IF your app calls a model THEN use `claude api` build eval to write a fixed test set once, then hill climb to keep only changes that score higher. Both cost real API money. Build eval also works without the API for apps that do not call a model.
- R10 IF you want the "clear context" option back after planning THEN set show clear context on plan accept to true. Plans are saved in a plans folder inside .claude. Use the plans directory setting to save plans in a project folder you share.
- R11 IF you want to explore an idea without losing your place THEN use branch (copies chat to a new session). Use fork to run a side task in a background copy. Use subtask to start a sub-agent with your full context.
- R12 IF several sessions work on one project THEN use list agents so one session can message another and get an answer while the other works.
- R13 IF you leave sessions unattended THEN set ask user question timeout (for example 60 seconds). Claude then takes the suggested answer if it can move on. It still waits when the question blocks progress. Also set local notifications through config (for example terminal bell).
- R14 IF you want to save usage THEN run model with `opus plan` so Opus plans and Sonnet builds. Set the sub-agent model setting plus its force setting (to 1) to make all sub-agents use one smaller model.
- R15 IF you return after long tasks THEN set TUI to full screen and run focus to see only your prompt, answer and a short summary.

## Features and facts mentioned (with version or date if given)
- Output styles: default, proactive, concise, explanatory, learning.
- Shortcuts: Ctrl S stashes a prompt, Ctrl Y restores deleted text, Ctrl underscore undoes the last prompt change. Ctrl O no longer shows reasoning summaries; a show thinking summaries setting brings them back.
- powerup command gives short lessons with animated demos.
- Claude Code starts in auto mode, which allows safe commands (as stated in the video).

## Mistakes to avoid
- Do not keep old instructions written for older models. They fill context and make answers worse.
- Do not leave unused skills and connectors loaded.
- Do not run eval or hill climb without budgeting API cost.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- Mostly developer settings. Useful general ideas: audit skills regularly, remove unused skills, disable unused connectors, set a timeout so unattended sessions keep moving.
