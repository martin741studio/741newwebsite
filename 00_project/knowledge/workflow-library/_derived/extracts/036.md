# 036 How Anthropic uses Claude Code: Agentic Software Engineering at Scale (Daisy Hollman)
Source: NDC Conferences, 2026-08-11, https://www.youtube.com/watch?v=shZgedW15vg
Reliability: High for Claude Code internals (speaker works on Claude Code at Anthropic; she led plugins and agent teams). Third-party conference channel, not an official Anthropic channel. She states some features may have changed while she was out of office. Opinions on the future are marked as such.

## Rules (IF situation THEN action. Why.)
- R1. IF you customize Claude Code THEN remember the context window is the basic limited space. System prompt, tool definitions, CLAUDE.md, skills, files read, and tool results all compete for it. Every customization competes with space for work.
- R2. IF you choose an extension type THEN follow "don't pay for what you don't use". Prefer things that put nothing in context unless relevant.
- R3. IF you want Claude to do your job with you THEN give it access to what you have access to (team chat, CI, dashboards, internal docs). Test: do a full day of work without leaving the terminal. If you cannot, Claude cannot do the job with you.
- R4. IF something in your workflow is copied and pasted into the prompt by you (CI failure, Slack thread) THEN connect it so Claude can fetch it.
- R5. IF knowledge is company-specific (conventions, past decisions, internal APIs, vocabulary, last week's changes) THEN put it in text in context. It cannot be trained into the model. Almost all customization happens in text ("in-context learning").
- R6. IF Claude makes tool mistakes THEN give a faster feedback loop. A PostToolUse hook can append text (type check, lint output, a reminder) to the tool result at the moment of the mistake. She says a tighter feedback loop beats a smarter model.
- R7. IF you build tools THEN prefer tools that scale with model intelligence (nudges and reminders) over tools that only compensate for weakness.
- R8. IF you have a command line tool already THEN write a skill that explains how to use the CLI, instead of building an MCP server. MCP is best for a public integration that works in any client.
- R9. IF you add many MCP servers THEN know that each tool's name, description, and schema sit in the system prompt. Tool search loads only names up front; a descriptive name makes Claude more likely to search for it. A tool named just "query" is rarely found. Many servers still dilute tool finding.
- R10. IF you write skills THEN know a skill is a folder with a markdown file (SKILL.md) plus optional resources. The description is always loaded in the system prompt; the body loads only when used. A very large number of skills would still fill the window. Skills have no hierarchy yet.
- R11. IF you want out-of-context work THEN use a subagent: its description is in the system prompt, but it runs in a separate context window and returns a compact summary. Skills are in context; subagents are out of context.
- R12. IF a rule must fire only in some situations THEN use a hook. Hooks run a script on events (tool use, prompt submit, stop, compaction). The script exits at once if irrelevant, so it costs no context. Pattern: determine relevance fast, quick exit if not, otherwise inject what matters.
- R13. IF you want always-on text THEN be aware that Claude Code plugins have no CLAUDE.md abstraction on purpose: it is low cost to write but high cost to use. If needed, use a SessionStart hook so the cost is visible.
- R14. IF you run several sessions THEN put each on its own worktree and label each with `/rename` and `/color`. Color helps recall.
- R15. IF you manage long-running work THEN give each worktree an agent with a persistent name and its own scratch files (her setup: named agents A to Z).

## Features and facts mentioned (with version or date if given)
- Edit tool is find-and-replace with old string and new string; old string must match exactly. She has not seen an edit-tool error since about Feb to April 2025.
- METR chart: task time horizon at 50% success doubles about every four months; the chart stopped being useful after Opus 4.7 and 4.8 (per speaker).
- Mozilla: April security fixes with the latest model exceeded the prior 15 months combined (per speaker).
- Frontier context windows are about 1 million tokens, as in Feb 2025.
- KV cache: a prediction with an unchanged prefix is much cheaper (she says about 10 times). Changing earlier context mid-session breaks the cache. Cursor found that swapping rules in and out cost a lot.
- Agent teams: SendMessage tool lets sessions message each other; leader/teammates or peers. Cross-machine messaging was announced.
- `/loop`: a cron tool for the model; it can turn itself off. Shipped about two months before the talk.
- Auto mode: classifiers check dangerous actions; costs about 10 to 40% more depending on model; enables multi-session work, loops, and overnight runs.
- Agent view / Fleet view: all sessions in one place with short classifier summaries.
- Remote control: use persistent agents on a server from phone or desktop.

## Mistakes to avoid
- Putting large text in always-loaded places (CLAUDE.md style, many skill descriptions).
- Loading many MCP servers with vague tool names.
- Swapping context mid-session (cache cost).
- Treating agent memory (model-written text files) as a context engineering primitive; she keeps memory and context engineering separate.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- Give Claude access to the tools you use daily (chat, drive, calendar) so it can do the full job.
- Company-specific knowledge (client rules, past decisions, vocabulary) must be in text files, not assumed.
- Skills (lazy-loaded) over always-on instructions; hooks for must-happen checks.
- `/loop` and auto mode for unattended recurring work.
- Persistent named agents per client area, like staff with identities.
