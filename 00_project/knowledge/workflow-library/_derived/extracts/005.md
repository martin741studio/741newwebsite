# 005 Getting started with Claude Managed Agents
Source: CJ Avilla (cjav_dev), 2026-10-07, https://www.youtube.com/watch?v=g1QfVjyrWzg
Reliability: Medium. Practitioner walkthrough of the console. Short and descriptive. No course sold.

## Rules (IF situation THEN action. Why.)
- R1 IF you want to start with managed agents THEN log in to platform.claude.com and open the quick start. Describe the agent and Claude generates it, or pick an example such as deep researcher.
- R2 IF you define an agent THEN set a name, description, model ID, effort level and system prompt. Add tools and metadata if needed. The config is YAML.
- R3 IF you need outbound network control THEN set it in the environment. Choose allowed domains only, or unrestricted. A deep researcher that crawls the web can be unrestricted.
- R4 IF you edit an agent THEN each save creates a new version. You can roll back to an earlier version.
- R5 IF the agent needs files and web access THEN use the built-in tools: bash, read, write, edit, find files, web search and fetch. Add MCP servers (for example Google Drive) for more.
- R6 IF the agent calls an MCP server or API with credentials THEN store them in a vault. The credentials are swapped in at the egress point, so the agent never sees your keys.
- R7 IF you want your own voice in outputs THEN attach custom skills (for example a brand voice skill). Built-in skills exist for PowerPoint and Docs.
- R8 IF one agent needs specialists THEN add a team of sub-agents (the video names Reddit and Twitter researchers).
- R9 IF you start a session THEN you can set a budget, for example "don't spend more than $5". The session runs the agent and emits events you can inspect in the dashboard.
- R10 IF you want runs on a schedule THEN use deployments to fire runs on a cron basis, for example a daily social media report.
- R11 IF an agent must remember across sessions THEN create a memory store. The agent writes notes at the end of a session and later sessions mount the same store.

## Features and facts mentioned (with version or date if given)
- An agent is a persisted, versioned config: a model, a system prompt and some tools.
- Max and Teams subscription API credits can now be used for platform features, including managed agents (stated as recent).
- A session is like a chat conversation. It can be started by a webhook, a cron job or an API call to create a session.
- The dashboard shows events: tools called, resources read and written, and threads.
- Left menu shows agents, environments, deployments and memory stores.
- The speaker has agents for code review, social media briefs, website management and podcast episodes from blog posts.

## Mistakes to avoid
- Do not give an agent raw API keys. Use the vault.
- Do not leave an environment unrestricted when the agent does not need the open web.
- The speaker names no explicit mistakes beyond these safety points.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- Scheduled deployments plus a brand-voice skill fit recurring client reports (daily or weekly briefs).
- Memory stores let a recurring agent keep notes between runs.
- Console setup needs no code, but it needs an API account on platform.claude.com.
