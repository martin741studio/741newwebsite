# 014 Every Claude Code Concept Explained in 9 Minutes (2026)
Source: Tech With Diego, 2026-09-30, https://www.youtube.com/watch?v=qlT4NyuWClU
Reliability: Medium. Practitioner (senior DevOps engineer) beginner overview. Mostly basic. No course sold, no speculation.

## Rules (IF situation THEN action. Why.)
- R1 IF you need Claude to touch your files and run commands THEN use Claude Code, not Claude Chat. Chat runs on Anthropic's servers and sees only what you type. Claude Code runs on your machine. You can open it in a terminal, an IDE like VS Code, or the desktop app. It is the same Claude Code in each.
- R2 IF you write a prompt THEN be specific, and use the @ symbol to mention files or folders.
- R3 IF you want to check spend THEN type /usage. Input, files read and responses all count as tokens, and tokens cost money.
- R4 IF you want to continue old work THEN type /resume. It lists previous sessions.
- R5 IF the context window fills up THEN you get context rot: Claude forgets early decisions or breaks things it fixed. Check with /context. Use /compact to summarize the session or /clear to start fresh (same as a new session).
- R6 IF you want a different model THEN use /model. Bigger models think better and cost more per token. Smaller models are cheaper and less capable. Context window size depends on the model.
- R7 IF you want Claude to think harder THEN use /effort. Use low for simple tasks and high for complex ones.
- R8 IF you set permissions THEN use an allow list (always allowed without asking) and a deny list (never allowed). Edit with /permissions.
- R9 IF you want a quick way to change how much Claude asks THEN switch mode with Shift Tab. Manual asks before every change. Accept edits writes files automatically but asks before other commands. Auto lets Claude decide when to ask for risky commands. Plan changes nothing and gives a step-by-step plan for you to approve.
- R10 IF you are tired of re-explaining the project THEN write a CLAUDE.md. Claude reads it at the start of every session. Put tools used, code style and rules there. There is a global one in the .claude folder and a project one in the project folder. /init writes one by analyzing the project.
- R11 IF you want to see what Claude saved itself THEN type /memory. Claude writes memory.md in the .claude folder.
- R12 IF a rule must run every time with no exceptions (for example run tests when a task ends) THEN use a hook, not CLAUDE.md. Skills are not deterministic. A hook has two parts: when it runs and what it runs.
- R13 IF you want to connect GitHub, Notion, Slack THEN use MCP and manage it with /mcp.
- R14 IF a job splits into parts THEN ask for sub-agents. Each gets its own context window and task and runs in parallel. Each should work in its own git worktree to avoid conflicts, then you merge.

## Features and facts mentioned (with version or date if given)
- A token is a piece of a word. Common words fit in one token, long words are split.
- A skill is a predefined set of instructions for a specific task (code review, security review, documentation).
- Skills + hooks + MCPs grouped into one package make a plugin (caption reads "app login", likely "plugin").
- MCP is an open standard for connecting AI tools to external services.
- Not covered: loops and headless mode.

## Mistakes to avoid
- Do not do everything in one session. Each session has a context limit.
- Do not trust CLAUDE.md alone for must-run rules. "Most of the time" is not guaranteed.
- Do not let agents edit the same copy of the project.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- Concepts of context window, CLAUDE.md, skills, modes (plan before acting) and permissions apply to any Claude work.
- Mostly coding oriented. No business examples.
