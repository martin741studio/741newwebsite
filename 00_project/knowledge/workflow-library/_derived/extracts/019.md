# 019 Claude Context Engineering Explained: From RAG to Knowledge Graphs
Source: Agentic AI Institute, 2026-09-09, https://www.youtube.com/watch?v=ckAMHYw8JmE
Reliability: Medium-low. 57-minute live class from an instructor who sells a cohort course (25% off offered). Teaching style is Q and A with a lot of filler. Conceptual, aimed at developers building agents. Several claims (for example "25% of agent problems come from compaction", "knowledge graphs cut context 30 to 50%") are stated without proof.

## Rules (IF situation THEN action. Why.)
- R1 IF someone asks what "context" is THEN it is more than the prompt. Context = user prompt (including attached files) + system prompt + memory + tool descriptions (including MCP connectors) + tool results + skill descriptions and loaded skills. The agent harness = model + company knowledge + memory + tools and skills + guardrails.
- R2 IF you add more context THEN expect three costs: the context window limit (speaker guesses 1 million tokens, about 5,000 pages, for the newest Opus), input-token cost, and latency. This is why context engineering exists.
- R3 IF you want to know how Claude builds context THEN it starts with zero, loads the system prompt, then CLAUDE.md, memory, skills, MCP, rules, then your prompt. It then reads files, runs tools, adds results, and repeats until the goal is met.
- R4 IF Claude needs information from files THEN it uses file system search (grep), semantic search, past conversations, tool results, sub-agents and compaction.
- R5 IF a research task would bloat the main window THEN use a sub-agent. It has its own context window and CLAUDE.md. In the demo it spent 10,000 tokens but returned a summary of 420 tokens to the main agent. Only the summary counts in the main context.
- R6 IF the context window fills up THEN compaction shrinks it. Compaction can lose what you gave it (the speaker says this is unsolved).
- R7 IF you evaluate context THEN check in this order: retrieval quality (did it retrieve everything needed to answer?), groundedness (is the answer based on the provided context, not made up?), then responsiveness. Other evaluators: tool call accuracy, tool input accuracy, tool output utilization.
- R8 IF a folder is too large for the model (for example 1,000 contracts) THEN build RAG: split files into chunks (for example 200 words), create embeddings, store them in a vector store, convert the question to a vector, retrieve similar chunks (cosine similarity) and add them to the prompt. In the example 5,000 pages became 30 pages.
- R9 IF RAG returns the wrong kind of answer (for example the interest rate formula instead of the rate) THEN the question is multi-hop. Try agentic RAG first.
- R10 IF agentic RAG still fails THEN consider a knowledge graph. Define an ontology (classes, properties, relationships), extract entity-relationship triplets, store them in a graph database (Neo4j, Neptune, Azure options), query with a graph query language, and add related terms (one or two levels out) to the query before retrieval.
- R11 IF you think about knowledge graphs THEN evaluate first. Only add a graph if evaluations show you are failing on context. It costs effort. Order: attach the folder in Claude, then vector store, then agentic RAG, then ontology and graph.

## Features and facts mentioned (with version or date if given)
- Claude app: you can connect a project or folder, add skills, and add connectors. Descriptions of all of these load into context.
- Claim: with knowledge graphs, context shrank by 30 to 50%.
- Claim: 25% of agent problems come from compaction (shown "some other day").
- Models named in the talk: Opus 5.6, GPT-6, Sonnet with 256k window (speaker's examples).
- Microsoft Fabric IQ and Foundry offer ontology and agent evaluation tools (speaker is excited, not tested here).
- Case study: a law firm needed a 300-page loan agreement summary. Interest rate can be a fixed rate or benchmark plus spread (benchmark such as LIBOR or SOFR, spoken as "cipher").

## Mistakes to avoid
- Do not send more context just because you can.
- Do not assume retrieval found everything. Measure it.
- Do not skip the evaluation and jump to knowledge graphs.
- Do not trust the model not to hallucinate even when it has the right context. Check groundedness.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- The definition of context (what loads into a session) helps explain why long CLAUDE.md files, many skills and many connectors slow Claude down.
- Sub-agents returning short summaries keep the main chat clean.
- RAG and knowledge graphs matter only for very large document sets (for example a big contract or client document archive). For normal client work, attaching a folder in Claude is the first step.
- The rest is developer material.
