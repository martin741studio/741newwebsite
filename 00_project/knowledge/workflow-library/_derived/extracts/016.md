# 016 Claude's Creator Just Told Us How to Actually Use Claude in 2026
Source: AI Edge, 2026-09-17, https://www.youtube.com/watch?v=tRmLQZJYQdA
Reliability: Medium-low. Practitioner who says he watched 100+ hours of Anthropic material and relays Boris's views second-hand. He sells a school community and cross-promotes his own loops and graph-engineering videos. Strong claims (Bun rewrite, prompt injection) are repeated, not checked.

## Rules (IF situation THEN action. Why.)
- R1 IF a new model ships THEN test it without your old instructions (ablation). Anthropic deletes most of Claude Code's system prompt with each new model and adds lines back one at a time. Boris advises deleting your CLAUDE.md every 6 months and seeing what the bare model does.
- R2 IF you trim your setup THEN delete lines that tell the model how to behave (think this way, respond this way). Keep three things: your context (who you are, your business), your goals, and your definition of what done looks like. The speaker still uses skills and memory.
- R3 IF the model keeps tripping on one thing THEN add one line back for it. Build up slowly.
- R4 IF you write a prompt THEN specify the output and how to verify success, not the steps. Over-specification is the most common mistake Boris sees. It limits the model. Mythos-class models like Fable do worse when you micromanage them.
- R5 IF you do not know how to do something THEN just ask Claude Code to get it done. The speaker dumped X links in and said "transcribe all of these".
- R6 IF you want to find the limit THEN give Claude one task a week that you think is not possible, or that you never delegate. Worst case you lose 10 minutes.
- R7 IF you want unattended runs THEN set Claude Code to auto mode and use a scheduled session or a loop, so Claude can verify its own work.
- R8 IF you have a recurring task THEN put one task on a schedule. Start with one high-leverage item (a business development research sweep, outreach, inbound deal flow, monthly accounting). Add one new automation each week. Do not build an agent army on day one.
- R9 IF you want a loop THEN use /goal for the final output and /loop for the interval. Example goal: scan a competitor channel, log titles and views per day to a tracker file, flag videos at 3x the channel median, "done = tracker updated, outliers flagged, stop after eight runs". Claude then runs mini verification loops.
- R10 IF you use Fable THEN tell it to default to the best model for each step. Fable acts as orchestrator and defers to Opus, Sonnet or Haiku. Fable is too expensive for most people (speaker's view).
- R11 IF you want to hand work to AI THEN map each workflow as a graph: each step says what, why and who (which AI with which skills, or a human who verifies). Make an HTML file for yourself and a markdown file for the AI. Keep a library of all workflows (Google Sheets, Notion or Excel). He split "land a client" into 20 SOPs and found 17 or 18 could be done by AI. Start with one process.

## Mistakes to avoid
- Do not give step-by-step instructions to new models.
- Do not keep old instructions written for older models.
- Do not stay in the loop yourself. The model verifies each step against your definition of done.
- Do not build too many automations at once.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- Directly relevant: pick one weekly task (research sweep, outreach, accounting) and schedule it. Define "done" before the run. Map client workflows as step lists with human check points.
- Keep client and business context in CLAUDE.md. Remove behavior rules.
- Treat the large claims as unverified.
