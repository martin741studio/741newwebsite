# 041 Anthropic's New Rules Break Most Claude Code Setups
Source: Eric Tech, 2026-07-29, https://www.youtube.com/watch?v=rYb_xSjx-Fw
Reliability: Medium. Practitioner walking through an Anthropic engineer's article (Thariq, "new rules of context engineering for Claude 5 models") and running `/doctor`. The article is the high-reliability part; the demo and opinions are the speaker's. Promotes a paid community. Same article as extract 042.

## Rules (IF situation THEN action. Why.)
- R1. IF you send a message THEN the prompt is only a small part of the context. The system prompt, skills, CLAUDE.md files, memories, and more assemble the rest. This is context engineering.
- R2. IF you switch to a new model THEN re-check the setup. A preset harness (system prompt, CLAUDE.md) built for an older model does not use what the new model can do.
- R3. IF instructions conflict THEN fix them. Example from the article: system prompt says "Do not add comments", CLAUDE.md says "Comment or document everything", prompt says "Make this readable". The model burns tokens reasoning about the contradiction.
- R4. IF your CLAUDE.md is a "kitchen sink" (the article's example: 1,400 lines, with test-running rules used in about 5% of sessions) THEN move rarely used parts into skills. CLAUDE.md loads in 100% of sessions.
- R5. IF you want to slim a setup THEN run `/doctor`. Per the speaker, Anthropic removed over 80% of Claude Code's system prompt for Opus 5 and Fable 5 with no measurable loss on coding evaluations (article claim as reported).
- R6. IF you run `/doctor` THEN expect it to audit, report, and ask before changing. It checks about 10 areas: install health, skills and MCPs, CLAUDE.md files, unused extensions, permission prompts you keep hitting, and more.
- R7. IF `/doctor` lists unused skills and plugins THEN cherry-pick what to keep and what to disable. It disables in settings and does not delete from disk. In his run: 36 user skills, 5 plugins, and 2 text edits to CLAUDE.md would give back roughly 6,000 tokens per session; the skill listing dropped from about 10,000 to 6,900 tokens, under the 10,000 cap that truncates the list.
- R8. IF several skills do the same job (two code-quality reviewers, two browser-testing skills) THEN keep one and disable the rest. Ask `/doctor` to group redundant skills. The model may not need the skill at all.
- R9. IF you use the second-brain pattern THEN run `/doctor` there too.

## Mistakes to avoid
- Reusing the same CLAUDE.md and system setup across model generations.
- Contradictory instructions across system prompt, CLAUDE.md, and prompt.
- Loading rarely used rules into every session.
- Keeping duplicate skills that do the same thing.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- Audit our own CLAUDE.md files and skills for conflicts and bloat.
- Move rarely used procedures (a specific report format) into skills.
- Remove duplicate SEO or browser skills.
- Note: `/doctor` is a Claude Code terminal command (the next extract says it was not visible in the desktop app).
