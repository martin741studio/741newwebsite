# 040 Claude Code Setup Guide By The Creator Himself
Source: AI LABS, 2026-07-31, https://www.youtube.com/watch?v=pGro_uKt-_M
Reliability: Medium. Second-hand summary of an interview with Boris Cherny (Claude Code creator), mixed with the channel's own opinions. Sponsor read (Buzzy Canvas) and a paid community plug. Cost numbers come from the speaker.

## Rules (IF situation THEN action. Why.)
- R1. IF a new model ships THEN re-test your setup. Your setup is CLAUDE.md, skills, hooks, and more. All are injected into context and stay there. Boris says people carry "dead weight" from older models. When Opus 5 shipped, Anthropic deleted about 80% of Claude Code's system prompt.
- R2. IF you want to know the cost of your setup THEN run `/context` in an empty session. About 3% of the 1M window is already used by the system prompt and built-in tools (you cannot change that). Everything above that is yours.
- R3. IF you want to test without your setup THEN use safe mode. It turns off CLAUDE.md files, skills, plugins, and everything installed. Run your usual tasks and watch the result. If it is fine, start cutting.
- R4. IF you decide what stays THEN ask one question: "Would Claude have worked this out on its own?" If yes, delete the line (example: "use npm run dev to start it"). Keep what differs from defaults (a specific test browser, a required service, your own test).
- R5. IF you want automatic trimming THEN run `/doctor`. It cuts what Claude could work out and keeps places where it made mistakes, the reasoning, and non-default behavior. It gives a health report with a verdict per piece; nothing changes until you approve.
- R6. IF you worry about installing outside skills THEN know Boris says newer models resist prompt injection. The speaker's test: a GitHub skill told the project to send data to a URL; Claude refused and said so in chat. Still read what you install.
- R7. IF you want long unattended work THEN define an eval first: a fixed check that decides "done" and can fail ("a check you can't fail isn't a check"). Write it before you build. Examples: page fits a phone screen, a wrong password does not get in, no em-dashes in text.
- R8. IF you rewrite a large system THEN use a parity check (run the old and new versions and compare outputs), a full test set, and reviewer agents that each look for one kind of problem. Boris's example: rewrite the Claude desktop app in Swift, screenshot the old app in a virtual Mac, compare pixel by pixel; it ran over 2 weeks.
- R9. IF checks all pass easily THEN replace them. Boris says checks last two or three model generations.
- R10. IF you prompt THEN say what you want, the limits, and what finished looks like. Do not say how. Experienced engineers are worst at telling the model how. Give tasks slightly harder than you think it can handle.
- R11. IF you give a design reference image THEN describe the style instead. A handed image returns a near copy. The same goes for ideas: a concrete example becomes something to copy.
- R12. IF the model keeps getting something wrong THEN pick the cheapest fix first: (1) clarify the prompt; (2) put always-true short facts in CLAUDE.md; (3) make a skill for things you explain the fifth time; (4) add an MCP server only when the information is out of reach.
- R13. IF you write a skill THEN keep it for what is particular to you or your team (Claude knows generic best practice). Split long skills across files so only needed parts load. CLAUDE.md loads at every session start; a skill loads only when needed.
- R14. IF a job is large THEN prefer routines over dynamic workflows with hundreds of agents. Routines run in the cloud after you close the laptop; Anthropic runs 20 to 30 a day, each one sentence (clean up unused code, write tests for untested parts, merge duplicates).

## Features and facts mentioned (with version or date if given)
- Opus 5 and Fable 5 are named. A usage command shows how much of the 5-hour window is burned and which skills or habits drive it.
- Claude launches headless Chrome by default and takes screenshots to check for overlaps.
- Dynamic workflow: say "use a workflow"; Claude plans waves of agents. The Bun rewrite (about 1 million lines in under two weeks) cost about $165,000 at API pricing, and 19 things broke that existing checks missed (per speaker).

## Mistakes to avoid
- Carrying a setup built for older models.
- Telling the model how instead of what.
- A check that cannot fail.
- Running hundreds of agents for two weeks on work you must ship.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- Write the "done" check before the work (mobile fit, correct facts, banned phrases).
- Describe style instead of pasting a reference to avoid copies.
- Routines as one-sentence recurring cleanups.
- Four-step fix ladder for repeated mistakes.
