# 030 The Ultimate Claude Code Tutorial (Beginner to Pro)
Source: Zinho Automates, 2026-08-17, https://www.youtube.com/watch?v=OVm2AGTxYuE
Reliability: Medium. Practitioner tutorial in the desktop app. Promotes a free community. Cites Anthropic engineers and a July post on context (not verified here). Gauntlet Loop is from a third-party builder.

## Rules (IF situation THEN action. Why.)
- R1. IF you are new THEN use Claude Code in the desktop app: sign in, click the Code tab, point at a folder. Chats are in the middle, project files on one side, a preview on the other.
- R2. IF you pick a model THEN keep Sonnet as default. Use Opus for hard problems (tricky logic, a stubborn bug). Use Fable 5 only when it truly counts: it is the sharpest coding model but pricey as a daily driver.
- R3. IF a problem is very hard THEN raise the effort setting to max (slower and pricier). Leave it on default otherwise.
- R4. IF you prompt THEN state five things: what you build, what it is for, what it must do, what it should look like, what it should never do.
- R5. IF you use the newest models THEN give a standard and let Claude reach it, instead of piling on rules and examples. Anthropic engineers say stacked rules box the model in and three samples make it copy them.
- R6. IF you start a build THEN use plan mode first. Claude reads files, thinks, and asks questions before you say go.
- R7. IF you describe the task THEN talk (mic) instead of typing. Typing compresses and cuts context; talking gives Claude more.
- R8. IF the first version is imperfect THEN describe what is off like a designer ("cards feel cramped") and loop: build, preview, describe, refine.
- R9. IF Claude says it is done THEN open the diff view to see what changed and what did not. You can comment on a line. Also run the built-in code review command (it targets real bugs, broken logic, security holes, not style).
- R10. IF something looks wrong visually THEN paste a screenshot and say "Fix this".
- R11. IF your CLAUDE.md is long THEN cut it. Treat it as a directory, not a warehouse. Keep only what Claude cannot learn from the code (brand voice, message style, one non-obvious architecture call) plus pointers to skill files. Test: "would a senior developer already know this from the folder?" If yes, cut it. His example file has three lines.
- R12. IF a process repeats THEN save it as a skill, trigger with a slash command or let Claude pull it when relevant. Put design rules in a design skill.
- R13. IF the usage meter (context) fills THEN `/compact` to keep the same session, `/clear` to switch to something different. Compact before you switch tasks.
- R14. IF you finish a session THEN run `/doctor` every few sessions. It finds unused skills, forgotten connectors, and CLAUDE.md bloat.
- R15. IF a job is big THEN run it in a cloud session or routine. Cloud sessions keep running after you close the app. Routines run on Anthropic's cloud on a schedule (for example review pull requests overnight, triage bugs Monday morning).

## Features and facts mentioned (with version or date if given)
- July 2026 (per speaker): Anthropic cut over 80% of Claude Code's own system prompt with no drop in coding performance.
- Parallel sessions side by side, each isolated. A side chat answers questions without interrupting the main build.
- "Gauntlet Loop" (Matt Schumer): three lines. Task; method (fan out subagents, each with a critic); bar (do not stop until every critic is satisfied). Visible in the workflows panel.
- Deploy to Vercel by asking in one sentence; Claude returns a live URL.
- Connectors menu adds tools (Google Sheets example).

## Mistakes to avoid
- Stacking "never/always" rules and examples.
- A giant CLAUDE.md that burns budget every session.
- Running the Gauntlet Loop on a weak idea: it polishes the wrong thing. Build a solid first version first. It also uses much time and tokens.
- Typing a compressed prompt instead of talking.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- Five-point prompt and "set the bar" mindset apply to client briefs.
- Voice dictation plus plan mode for big deliverables.
- Thin CLAUDE.md with brand voice and pointers to skills; matches client-specific style files.
- Screenshot-and-fix loop for page layouts.
- Routines for scheduled client checks.
