# 025 Claude Code Hooks, Explained Simply
Source: Agentic Lab, 2026-08-27, https://www.youtube.com/watch?v=AP7c9YTcaw8
Reliability: Medium. Practitioner opinion, short. Promotes a free community. No version numbers.

## Rules (IF situation THEN action. Why.)
- R1. IF you want to understand a hook THEN think: a hook is an event that triggers a script. The event says when. The script says what.
- R2. IF a rule in CLAUDE.md must always be followed THEN move it into a hook. The model is probabilistic and may ignore CLAUDE.md rules in a long session. A script is cheap, instant, and identical every time.
- R3. IF a check is binary and mechanical THEN put it in a hook. IF it needs judgment THEN keep it at the prompt level (skill, `.claude/rules`, prompt).
- R4. IF you set up a hook THEN write the prompt in four parts: event (when), behavior (what the script does), why (your motivation), edge cases (keep few; eval the hook instead of predefining every case).
- R5. IF you set up a hook THEN let Claude write the schema and wiring. You describe the four parts in plain words.
- R6. IF unsure what you want THEN use "bidirectional prompting": ask the model to ask you a few questions first.
- R7. IF a hook should run only for some tools THEN add a matcher (for example matcher `Bash` on a PreToolUse hook). It works like an if statement and stops the hook from running constantly.
- R8. IF a hook is only needed when one skill or custom agent is active THEN put the hook inside that skill or agent. It is active only in sessions that invoke it.
- R9. IF you want a second opinion after Claude stops THEN use a hook that spawns another Claude Code or Codex instance to red-team the implementation.
- R10. IF you want persistent memory THEN use a SessionEnd hook that spawns a forked `claude -p` agent to summarize the session into a markdown knowledge-base folder. Watch for knowledge-base bloat. Do not let subagents or automations summarize their own sessions.
- R11. TODAY: open your CLAUDE.md and rules files, read every line, and ask "could this be a hook instead?" Move those lines to hooks to remove bloat.

## Features and facts mentioned (with version or date if given)
- Lifecycle events named: user submits a prompt, Claude compacts, subagent spawned, tool called, session begins, session ends.
- In recent months hooks can trigger an HTTP call, an MCP tool, a prompt, or spawn a subagent (no version given).
- Hooks sit in the harness layer, above prompt-level instructions.
- The Anthropic docs say hooks make actions "always happen" rather than relying on the model.

## Mistakes to avoid
- Relying on CLAUDE.md alone for must-happen behavior.
- Predefining a long list of edge cases.
- Letting auto-summary hooks summarize their own subagent sessions (loops, bloat).

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- Mandatory checks before delivery (for example block publish if a data point is unverified) belong in a hook, not a note.
- Session-end summaries into a client knowledge folder give long-term memory.
- Hooks inside a skill let a client-specific skill enforce its own rules only when used.
