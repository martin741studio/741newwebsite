# 035 What Is Context Engineering? Why It Matters for AI Agents
Source: IBM Technology, 2026-08-11, https://www.youtube.com/watch?v=Qx0fCqpkBus
Reliability: Medium-high for concepts (explainer from a large company, not Anthropic). Generic, not about Claude features. No Claude commands or file names.

## Rules (IF situation THEN action. Why.)
- R1. IF you build agents or workflows THEN think of context engineering, not only prompt engineering. Prompt engineering asks how to phrase instructions. Context engineering structures the entire information environment. Prompt engineering is one part of it.
- R2. IF you have a huge context window THEN still be selective. More context does not mean better performance. Performance can degrade as context grows ("context rot"): irrelevant, badly structured, or missing data causes worse reasoning and hallucinations.
- R3. IF you add information THEN make it relevant. Each item should help the model finish the task.
- R4. IF you add information THEN give it structure: labels and formatting so the model can tell information types apart.
- R5. IF you run agents THEN introduce context only when needed (timing).
- R6. IF you have raw data THEN compress it. Summarize or filter to the most useful details instead of dumping it in the prompt. Relevance, structure, timing, and compression together are "context processing".
- R7. IF a session runs across many steps THEN manage context over time: decide what to keep and what to discard, keep continuity across interactions, and prioritize by relevance, recency, and importance.
- R8. IF new information arrives THEN update the context and invalidate outdated data. Keep it consistent and coherent.
- R9. IF a task depends on rules and live data THEN supply them. Example: a scheduling assistant gets clinic policies (appointment types and durations), the doctor's real-time availability, patient preferences (mornings only), relevant history, and tool output (open slots from a scheduling API). Then the model reasons instead of guessing.

## Features and facts mentioned (with version or date if given)
- Definition: context engineering is deliberately structuring and optimizing the information passed to an LLM or agent for more accurate, relevant outputs.
- Context = system prompt, user query, retrieved documents (vector database or document store), conversation history, and outputs from tools, APIs, or other agents.
- Human working memory holds about three to five items for about 20 seconds (recent research, per the speaker).
- Models with 2 million plus token windows are mentioned.

## Mistakes to avoid
- Dumping 4,000 pages of Slack, email, and notes on the model and expecting it to find what matters.
- Giving a bare prompt ("Schedule an appointment for this patient") with no rules, availability, or history.
- Keeping outdated information in context.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- The scheduling example fits agency work: supply the client's rules, calendar availability, and preferences, then ask for the plan.
- Give Claude a one-page brief per client, not the full archive.
- Summarize old notes before reuse; remove outdated client facts.
