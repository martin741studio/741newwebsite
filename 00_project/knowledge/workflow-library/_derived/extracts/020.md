# 020 How founders build on Claude Managed Agents
Source: Claude, 2026-09-08, https://www.youtube.com/watch?v=hm8NzEd5io0
Reliability: High for what Managed Agents offers (official Claude channel). Medium for the claims: it is a roundtable of four startup founders who are customers, and the host is from Anthropic. Not a tutorial. No commands or setup steps.

## Rules (IF situation THEN action. Why.)
- R1 IF a wrong output is worse than no output THEN use "outcomes". An outcome is a rubric you give the agent. The agent iterates until the rubric is satisfied. If it fails, show the user nothing. A wrong meeting brief ("wrong Tom") is "almost destructive".
- R2 IF you write a rubric THEN include objective checks (is it the right person's LinkedIn?) and presentation checks (scannable, right order: who, why meeting, what to do). Avoid a five-page pre-read nobody reads.
- R3 IF you need quality control THEN use an independent verifier. Managed Agents grade the work in a separate, clean context window. The agent that does the work should not be the only judge.
- R4 IF the agent works ahead of time THEN run it early. Example: briefs run 24 hours before the meeting. That leaves time to assess and fix.
- R5 IF the agent is proactive THEN choose silence over a guess. "Help when you can and do not cause harm or annoyance."
- R6 IF a task spans many accounts THEN use a coordinating agent that writes code, narrows the candidate set, and fans out to independent agents per account. Then it rolls the results up.
- R7 IF you use cheaper models THEN use them for the wide fan-out. Keep the frontier model (Opus) for the coordinator. One founder fanned out over 500 accounts with cheaper models.
- R8 IF memory is core to your product THEN own it. IF memory is generic (field meanings, org rules, user preferences) THEN use managed memory. One team keeps its per-account memory itself and uses managed memory for the rest.
- R9 IF you learn company-specific concepts THEN ask the user once, then save the answer to org-wide memory. This avoids heavy setup config.
- R10 IF code or secrets are involved THEN run in a sandbox. Control the tools, the data, and the actions. Pull requests are the typical result.
- R11 IF the harness is not your core skill THEN buy (use Managed Agents). IF the harness is the product (e.g. a voice-controlled "Jarvis") THEN build your own. A fourth reason to buy: you are validating viability, when learning time is the cost.
- R12 IF the product is not yet sticky THEN use "vibes" first, then build evals. Build evals from real customer queries, not only internal dogfooding.
- R13 IF a new model ships THEN run your eval suite, and watch for new failure modes (the "five series" writes more AI tells, such as em dashes) instead of tuning the last 1 percent.

## Features and facts mentioned (with version or date if given)
- Managed Agents features named: outcomes (rubric plus independent verifier), memory, sandboxing, managed prompt caching, multi-agent, effort settings.
- Founders report 2 weeks from idea to shipped product, and a first version of a feature in a day.
- Missing today per founders: batch or flex mode (est. 50-75% savings for jobs run 24 h ahead), finer cost levers, sandbox pre-warming for latency.
- Memory scopes: account level, cross-account level, user level, org level.
- Evals are hard with stateful memory and third-party MCP tools that change over time.

## Mistakes to avoid
- Showing unverified output to the user.
- Evals that are too abstract or built only from internal dogfooding.
- Over-optimizing cost too early. One speaker: be mindful, then optimize later.
- Rolling your own sandbox and edge cases when it is not your core value.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- Rubric plus separate checker is a good pattern for client deliverables: define checks first, let a second pass grade, and send nothing that fails.
- "Prep before the meeting" brief, run a day ahead: fits client call prep.
- Nightly checks on yesterday's metrics (funnel drop, week-over-week slide) map to rank or lead monitoring.
- Managed Agents need developer work. Treat as background only.
