# 001 Getting started with Claude Code Projects
Source: Claude, 2026-10-09, https://www.youtube.com/watch?v=omihvjf0A2k
Reliability: High. Official Claude channel. Feature is in beta, so details may change.

## Rules (IF situation THEN action. Why.)
- R1 IF a goal is too big for one session or spans several repos THEN start a Claude Code Project. A project is one ongoing conversation where Claude coordinates the work.
- R2 IF you create a project THEN give it three things: a project name, a goal, and the relevant repos or folders.
- R3 IF you have a list of tasks THEN give the list to the main conversation. Claude spins up one thread per task. You do not manage sub-agents, sessions or worktrees yourself.
- R4 IF you want to understand the goal first THEN ask Claude to explore the codebase and suggest work. Agree on the tasks, then let it start threads.
- R5 IF a thread needs your local files or tools THEN ask Claude to run that thread on your computer. By default a thread runs on its own branch in the cloud.
- R6 IF you want to follow or correct a thread THEN click its card. You can steer it by talking in the thread, or stop it.
- R7 IF a thread has a concrete change ready (for example a bug fix) THEN it opens a pull request by itself or when you ask. The thread then watches the PR, pushes fixes when CI fails, and answers review comments.
- R8 IF you want a shareable summary THEN ask Claude to create an artifact. Artifacts live in the library tab, the project's shared folder. Every thread can read it, so the next run can update the report.
- R9 IF you want to catch problems early THEN connect a monitoring service and ask Claude to set up a routine that runs every day. If it finds a regression, it opens a thread and waits for you in the project.
- R10 IF usage runs too fast THEN lower model and effort in project settings. Keep the coordinator on low effort because it mostly routes work. Default threads to a smaller model. Switch to a bigger model in the thread for complex tasks.
- R11 IF you want a specific working style THEN tell Claude: how many threads at once, how often to update you, or to show a plan before it starts.
- R12 IF you want a preference to last THEN tell Claude to remember it. Threads share memory. Edit the memory in project settings.

## Features and facts mentioned (with version or date if given)
- Claude Code Projects: one ongoing conversation, many threads. Beta, rolling out gradually to Pro and Max plans (video dated 2026-10-09).
- A thread is a full Claude Code session with its own branch, running in the cloud. Work continues after you close the laptop. You can check in from your phone.
- Threads tab shows threads waiting for you. Pull requests tab (in overview) shows all PRs and status. Library tab holds artifacts and files you add (mock-ups, design spec).
- Ask Claude to merge when you are ready.
- Example uses: migrate off a deprecated package, update one endpoint across API, web and mobile repos.

## Mistakes to avoid
- Do not run many threads on a big model without checking usage. Each thread is a full session and uses plan limits faster than one session.
- Do not set the coordinator to high effort. It will not improve results meaningfully.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- The library as a shared folder per project fits client work: one project per client, with reports as artifacts that later runs update.
- A daily routine that checks a metric and opens an investigation thread on a drop fits ranking or traffic monitoring. The video only shows website performance, not SEO.
- The video is code-focused (repos, PRs). Non-code use is not shown.
