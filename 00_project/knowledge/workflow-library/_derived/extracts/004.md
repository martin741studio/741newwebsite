# 004 Anthropic Engineers Just 10x'd Everyone's Claude Code
Source: Nate Herk | AI Automation, 2026-10-08, https://www.youtube.com/watch?v=oz2CwrPV2Rg
Reliability: Medium. Practitioner summarizing an Anthropic engineer's article, with his own tests. Runs a community and has a sponsor segment (Hyper Agent). Title claim "10x" is marketing.

## Rules (IF situation THEN action. Why.)
- R1 IF you use newer models (Opus 5, Fable 5 and 5.1) THEN give less instruction. Anthropic removed over 80% of the Claude Code system prompt with no measurable loss on its evaluations.
- R2 IF you give a task THEN define what done looks like: the outcome you want, why you want it, and the constraints. Then leave the model room to work.
- R3 IF you write context THEN use the smallest amount that gets the highest quality result at the lowest cost. Minimal does not mean short. Keep any detail the model needs.
- R4 IF Claude makes a mistake THEN do not add a rule by reflex. Old rules pile up in CLAUDE.md and skills, in several slightly different copies, and may now restrict a better model.
- R5 IF you review a skill THEN keep the context Claude cannot infer or look up: your voice, goals, audience, how your business works, and the intent behind the task. Test whether the step-by-step procedure is still needed.
- R6 IF the same instruction appears in several places THEN check whether you need all copies. Look up-able items such as long folder listings can go.
- R7 IF a detailed procedure applies only to one job (for example video editing) THEN load it only for that job. Keep CLAUDE.md as a starting point: what the project is for, gotchas, and pointers to deeper instructions.
- R8 IF you want an audit THEN run /doctor. It checks skills (with usage counts and token estimate of the YAML front matter), memory, plugins, settings, installation, auto mode, permissions and hooks. It then offers to fix problems.
- R9 IF /doctor flags unused skills THEN review the list before deleting. Usage records only cover Claude Code, not other tools.
- R10 IF you want a workflow audit THEN prompt: audit the repo, show the smallest change that speeds up the path, cite the exact files you would reuse, and do not edit anything yet.
- R11 IF a new model drops and you switch THEN run the audit again. Otherwise run it monthly (many changes) or quarterly (stable setup). Each model reads your settings differently.
- R12 IF you trust the audit THEN schedule it as a local scheduled task in the Claude desktop app (app must stay open). Approve or deny the recommendations each morning.

## Features and facts mentioned (with version or date if given)
- Article by an Anthropic engineer: "the new rules of context engineering" for the Claude 5 generation. Anthropic's applied AI team recommends the smallest context that works.
- Boris (creator of Claude Code; surname garbled in captions) is quoted: roughly every 6 months, delete all your skills.
- 2025 paper on 5 models: performance dropped 13.9% to 85% as input got longer. These were controlled experiments and may not apply to your CLAUDE.md.
- Anthropic loaded MCP tool definitions only when needed: 85% less token use. MCP evaluation scores rose from 49% to 74% (Opus 4) and from 79.5% to 88.1% (Opus 4.5).
- /doctor example: agent-builder skill about 111 tokens, another 103 tokens, both zero uses. It flagged 18 old unused skills, about 2,250 characters of cuts (563 tokens), and a second CLAUDE.md from another folder costing about 2,000 tokens.
- /doctor found two broken skills: one wrong file name, one broken front matter.
- Memory sources listed: project CLAUDE.md, user-wide CLAUDE.md, auto-memory index, CLAUDE.local.md.
- Audit counted 25 video folders with a script but only 3 with sources.md.

## Mistakes to avoid
- Do not confine a strong model with heavy guardrails written for Opus 4.
- Do not leave a skill with broken front matter. Claude then cannot see its description.
- Do not forget instructions loaded from other folders.

## Relevant for a non-developer business workflow (SEO/marketing agency, Cowork, scheduling, client deliverables)
- Keep brand, voice, audience and client facts in context. Let Claude decide structure. Add branding as a separate skill after.
- A monthly scheduled audit of skills and CLAUDE.md files suits an agency with many client skills.
- Split work into steps with a saved evidence file (sources.md) passed to the next step.
