# O01 Search Console: Managing owners, users, and permissions
Source: official-docs/gsc-managing-owners-users-permissions.md, OFFICIAL, living page fetched 2026-10-12, https://support.google.com/webmasters/answer/7687615?hl=en
Reliability: High. Google Search Console Help. Primary source for roles and removal behaviour.

## Practice from this source
- A property has four roles: Owner, Full user, Restricted user, Associate. Owners are either "verified" (own token on the site) or "delegated" (added by an owner in the user screen).
- Only an owner can add or remove users. Full and restricted users cannot change the user list.
- The permission table marks "Disavow links" for Owner and Full user. The disavow help page (O02) says "You must be a property owner to upload a disavow list." Treat owner as the safe requirement.
- An owner removes a user under Settings > Users and permissions > menu > Remove access. The change takes effect "very quickly".
- If the removed person was a verified owner, the screen warns that the person "might regain access" with unused ownership tokens. The owner must delete those tokens to stop it.
- If the owner does not delete the tokens, the removed owner can re-verify. All current owners are notified when this happens.
- A verified owner cannot be downgraded. The owner can only remove that person.
- "Don't recognize an owner?" Google says you "might have been hacked". An unknown owner is a security signal.
- A property must have at least one verified owner. If all verified owners go, all users lose access after a grace period. Data collection continues.
- Limits: max 100 non-owners. Delegated owners up to 500 total owners.

## Use for client-access-lockout
- B: The client, as owner, can remove the agency at any time. The agency cannot block this. Access comes back only by a new invitation from an owner, or by re-verification with a token.
- B/F: If the agency still has a verification token on the site, re-verifying against the client's will is technically possible but notifies the client. Do not do this without written consent. It destroys trust.
- A: The client may see "you were removed" as a security step. Explain the roles neutrally.

## Limits
- The page does not say what a removed user keeps (exports, history). Data stays with the property, not with the user.
- The table and the disavow page conflict on who may upload a disavow file.
