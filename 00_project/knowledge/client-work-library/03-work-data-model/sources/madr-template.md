- Fetched: 2026-10-13

## Key points
- A decision record has a status, a date and the decision-makers.
- It names people consulted (two-way talk) and people informed (one-way updates). This is a light form of RACI.
- Required parts: context and problem statement, considered options, and decision outcome with the reason.
- Optional parts: decision drivers, consequences (good and bad), confirmation, pros and cons, more information.
- Confirmation says how the team checks that the decision holds, for example a review or a test.
- Status values include proposed, rejected, accepted, deprecated and "superseded by" a newer record.
- The context can link to issue trackers. This ties decisions to work items.
- Gaps / bias notes: The page gives little lifecycle guidance. It targets software architecture, so an agency must adapt it to client decisions.
