# Client portals: a delivery-first guide to client projects that actually protects margin
- URL: https://www.teamwork.com/blog/client-portals/
- Type: Vendor blog article (project-management software for agencies)
- Published: 2026-09-17 (byline; footer shows the same update date)
- Fetched: 2026-10-13
## Key points
- The article gives a four-step ladder for portals: (1) tidy hub, (2) status window, (3) working space, (4) margin line. Each step includes the step below it.
- Step 2 (status window): the client sees live status, milestones and reports. The data comes from the work itself, not from a manual copy.
- Step 3 (working space): the client approves deliverables and gives feedback in context. This makes an audit trail.
- Step 4 (margin line): the client and the account team see budget burn and scope in one view. Scope changes get a price early.
- Each client sees only their own projects. Access comes from permissions, not from a shared guest link.
- Status that someone updates by hand adds work. Status must come from live delivery data.
- The article compares a monthly emailed deck with real-time visibility. It treats real-time visibility as the goal.
- Small favors that nobody logs reduce margin. Visible scope lets both sides discuss changes early.
- Core idea in one quote: "A portal is only as valuable as the delivery data sitting behind it."
## Gaps / bias notes
- Vendor content. It sells the "margin line" step, which needs time tracking.
- It does not list which internal items to hide.
- No user research or client survey. The ladder is an opinion model.
