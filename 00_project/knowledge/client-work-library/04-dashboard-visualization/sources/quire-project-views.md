# Project views explained

## Key points
- Each view answers one question. Pick the view that answers the recurring question of the project.
- Timeline: when work happens and what depends on what. Use it when order and dates are the main risk.
- Board: where work is now and where queues grow. Use it for continuous flow, such as content production.
- Calendar: what falls on a given day and how full that day is.
- Table: compare many records on shared fields (owner, status, cost). Use it to find the one record that is wrong.
- Planners, doers and reporters ask different questions. One project often needs more than one view.
- Extra views must read the same tasks. Copies drift in days and make competing plans.
- Pitfalls: timelines for work that changes often go out of date fast. Boards hide hard dependencies. Views on blank dates or blank fields mislead.
- Check the chosen view again at each phase change.
