## Key points
- Agents appear in the same assignee menu as people. You delegate an issue to an agent when you assign it.
- You can also call an agent with an @mention in a comment or a description.
- An admin installs each agent and selects the teams that can use it. Humans keep control of access.
- Each agent has a user page. The page shows its issue activity and its contributions.
- Delegated issues stay in the delegator's "My issues" view. The human can follow the work in progress.
- A "Delegate" filter in views and Insights shows how much work agents handle.
- Workspace or team guidance tells agents the house rules, for example which repository to use.
- Agents cannot sign in, use admin functions, or manage users.
- Gaps / bias notes: The page does not define who is accountable for agent output. It does not give agent-specific status values. Vendor doc, written for software teams.
