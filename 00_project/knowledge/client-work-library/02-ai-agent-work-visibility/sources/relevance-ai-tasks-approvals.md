## Key points
- A "Task" is one run of work by an agent or a group of agents (a "workforce").
- The Tasks page has four tabs. Approvals holds runs that wait for a human. Escalated holds runs where the agent asks a question.
- Errors holds tool or runtime failures. All tasks lists every run.
- A human can approve or reject pending items in bulk. A human can rerun failed tasks from the step that failed.
- A confirmation box shows how many tasks a bulk action changes before it runs.
- Three approval modes exist per connection: Auto Run, Approval Required, and Let Agent Decide.
- Auto Run can have a cap on the number of automatic runs.
- Approval Required suits external messages, high-risk actions, and new workflows.
- The reviewer sees the proposed action and the reasoning of the agent. The reviewer can approve, reject, or give guidance.
- Escalations name a path (a human role or another agent) and a format. They can alert through Slack or email.
- Pending approvals stay open until a human acts. A team can set timeouts or reminders.

## Gaps / bias notes
- The pages are undated and exist in several URL versions with small differences.
- The pages do not say if a task shows cost or credits.
- Vendor doc. It gives no data on how well the modes work.
