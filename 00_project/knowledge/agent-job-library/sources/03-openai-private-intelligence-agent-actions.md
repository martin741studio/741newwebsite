# 03 — OpenAI Private Intelligence page (Agent actions pillar)

Type: vendor product page (primary source named in the video). Fetched 2026-11-03.
URL: https://openai.com/business/private-intelligence/ (announced 2026-10-30; sub-page "privacy by product" at /privacy-by-product/)

## What the page says (verbatim where it matters)
- Headline: "Privacy should advance as fast as intelligence."
- Four pillars: Access restrictions · Data ownership · Agent actions · Data security.
- Agent actions: "You decide what agents can access, which actions they can take, and when they need your approval."
- Section "You set the boundaries before agents act", four bullets: Data access · Available tools · Permitted actions · Required approvals.
- Rest: Zero Data Retention (eligible API workflows), Private Inference preview (confidential computing), compliance (SOC 2, ISO, HIPAA BAA, FedRAMP).
- Third-party coverage (zeniteq, smartscope, atlacis, all 2026-10-30/31) adds: product-specific configuration lets enterprise customers "choose app connections, control supported actions and set automation permissions"; "auto review / approvals" is the illustrated UI.

## Assessment for 741
New vs. video: the four-bullet boundary list (data access, available tools, permitted actions, required approvals) is a cleaner field set than Tyler's "locked tools + approval gate". It separates WHAT the agent can read from WHAT it can do from WHEN it must stop.
Marketing: it is a sales page; no mechanism is described; no definition of which actions need approval. The video treats it as validation; it validates only the vocabulary.
Usable for 741: adopt the four boundary fields as mandatory sections of every job description: (1) data it may read, (2) tools it may use, (3) actions it may take alone, (4) actions that need Martin's go. 741 already enforces (4) with the go-gate hook; the job description must name the actions that hook covers and the ones it does not.
