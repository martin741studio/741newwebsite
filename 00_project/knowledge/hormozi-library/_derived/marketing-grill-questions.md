# Marketing Grill question bank — per card round

Derived 2026-10-25 for the `marketing-grill` workflow. Each question lists what it is grounded in, so a live run can adapt the exact wording to the real situation found in Step 0 (the read phase), rather than asking a fixed script. Src references match `marketing-grill-rules.md`.

## Before Round 1 — orientation (not a card, read-only)
- Does a recent diagnosis already exist (e.g. a status check in `revenue-model-100k.md`, a prior playbook in `00_project/assets/741studio/marketing-grill/`)? If yes, Round 1 confirms/adjusts that diagnosis instead of re-deriving from a blank slate (R-MG1.1-1.4, confirmed useful in the 2026-10-25 hand-run).
- What is the real state of each Core Four channel right now (not from memory — read the actual infra/campaign memory files fresh)?

## Round 1 — what marketing to do
- Which of the Core Four best fits the current situation: is the offer proven enough to scale outreach/ads (R-MG1.4), or does the offer need fixing first?
- Is organic content currently the primary lead source, or the nurture/proof layer (R-MG1.2)? If it is being asked to carry primary lead generation, flag the 12-18 month lag (R-MG1.1).
- Is the traffic being pursued intent-based or interruption-based (R-MG1.3), and does that match the channel being considered?

## Round 2 — where to reach people
- Does the channel choice match 741's real avatar (agency owners / high-ticket local-service owners), not the health-client roster (R-MG2.1)?
- Which Lead Getter layer is most available right now: referrals, an affiliate/partner stream, a hired agency, or an employee (R-MG2.2)? Is capacity the constraint, or is the existing channel itself unproven?
- If a channel is currently outsourced, which phase of the in-house transition is it in (R-MG2.3)?
- Before naming any specific team member or owner in a card: has it been checked against the current `team-roster.md`, or should it be asked instead of stated (R-MG2.4)?

## Round 3 — how to focus and double down
- Is the chosen channel underperforming for a diagnosable reason (account health, tool, execution speed), or is it genuinely untested (R-MG3.1)?
- What is the volume/consistency commitment — a Rule-of-100-style daily action, or a narrower fix-first commitment matching a known diagnosis (R-MG3.2)?
- Is more than one channel currently getting attention? If so, which ONE gets depth-first priority (R-MG3.3)?
- What should explicitly stop, if anything — asked openly, with "nothing stops" as a real answer (R-MG3.4)?

## Round 4 — how the activity is structured
- Who owns the daily execution of this fix or channel — confirmed with Martin, not assumed from an old memory file?
- What counts as "done" for a day or a week (a volume number, a speed-to-contact rule, R-MG4.1/4.2)?
- How fast does a new inbound lead or request get a reply (R-MG4.1)?
- Where does this show up day to day — the existing Morning Grill / Command Center, or does it need something new (R-MG4.3, default: route into the existing system)?
