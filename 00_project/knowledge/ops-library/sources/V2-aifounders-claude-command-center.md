## Key points (paraphrased from transcript)

1. Let Claude **interview you** first (role, repeated weekly decisions, what you keep looking for, what you wish you knew sooner). Output: a command center brief.
2. Cut the brief hard. Filter for every item: if this changed tomorrow, would I do anything differently? If not, drop it (e.g. a 4% traffic change). Keep escalation-worthy items.
3. Final layout: today, needs attention (with the reason why), a handful of key numbers, upcoming meetings, **decisions waiting**.
4. **Source map**: a table per item: information needed, source of truth, and a column "can Claude prove it sees it?". Name one trusted source when the same number appears in several places.
5. **Visibility check** before building: Claude must show one real example from each source. His calendar showed zero meetings because the wrong calendar was shared. A dashboard that looks right but reads incomplete data is the most dangerous kind.
6. Build the page as a connected artifact that refreshes from connectors when reopened.
7. Use a scheduled task only for narrow alert conditions (issue reaches a level, project blocked, important meeting unprepared, threshold crossed). If anything can interrupt you, nothing is a priority.

## Use for 741

Gives the "would I act differently?" filter for the brief, the source map + visibility check as a pre-flight gate for each client data source, and the rule to keep push interrupts narrow.

Short quote: "Information has no value until it changes a decision."
