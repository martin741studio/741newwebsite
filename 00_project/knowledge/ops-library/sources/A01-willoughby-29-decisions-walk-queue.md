# A01 — My Morning Is 29 Decisions and a Walk Queue

- Author: Dan Willoughby (founder, "Both Things Are True" newsletter, The Operator's Log)
- URL: https://danrwilloughby.substack.com/p/my-morning-is-29-decisions-and-a
- Type: practitioner essay (founder running an AI-heavy company)
- Publish date: 2026-08-27 (shown on page. Modified 2026-08-28)
- Fetch date: 2026-10-13

## Key points (paraphrased)

1. Agents build overnight and assemble a **decision board** by morning: every decision that blocks work, ranked. One July board held 29 cards.
2. Core lesson: the hard part is not deciding, it is loading enough context to decide well.
3. Version 1 used agent jargon (unit IDs, plan refs) and failed. Standing rule since: each card opens in plain language with what it is part of, why it matters now, and what an answer makes possible. Technical detail comes after.
4. Each card links evidence pages. A card without evidence is treated as a request for blind trust.
5. Each card offers lettered options plus a **mandatory recommendation**. A menu without a recommendation is banned.
6. Martin-equivalent answers in one compressed string such as `1p 2a 3a 8p 9b` (card number + option letter, `p` = park). The system records the string and executes it overnight. Seventeen decisions in one sitting unblocked several workstreams.
7. **Park** is a first-class answer. A park needs a reason. The reason is binding. The card does not resurface until that reason changes. This stopped the same half-decisions coming back every week.
8. "I lack context to rule" is a valid park reason. The system treats it as a failure of the card's context layer, not of the decider.
9. **The board argues back**: when the founder claimed something "had already moved on", the system checked the record, found it false, kept the card open and flagged it. Fact-checking must go upward too.
10. What does not compress into letters: walking features in a live browser before customers see them (the "walk queue"), killing renders on taste, pausing a whole effort when thinking changes, choosing fixes by blast radius.
11. The founder job that remains: deciding, verifying, owning outcomes.
