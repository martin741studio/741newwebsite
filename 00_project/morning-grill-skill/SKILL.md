# Morning Grill

Spec: `00_project/morning-grill-workflow.md` (read §1, §5, §8 at the start of every run). Preferences: `00_project/assets/morning-grill/preferences.md` (read every run, never edit). Goal sheet: `00_project/morning-grill-goals.json` (GENERATED, see below — never hand-edit it).

## Critical
- `00_project/morning-grill-goals.json` is generated, never hand-edited (go 2026-10-15, `references/goals-architecture.md`). Edit Supabase (goal numbers, status, phase) for a portal client, or `00_project/morning-grill-goals-overlay.json` for everything else (aliases, chat, client_rules, blockers, waiting_for, non-portal clients, leads).
- Open points never as a prose list: ask them as cards in the same grill (D19).
- The scan is READ ONLY, with one exception approved 13.10.: `publish_snapshot.py` inserts ONE row into grill_snapshots; `pull_answers.py` only reads grill_answers. Never send, publish, spend, or change a portal, site or table. Message drafts go in ```text blocks, slop-checked 5/5.
- Never mark a task "done". Never invent a number: `null` plus a define card.
- A source that fails is "unreadable" in the brief, never "nothing new". Time zone is WITA (UTC+8).

## Mode B — Evening (17:00 task or "log the day")
- [ ] 1 Same sources since the morning bookmark (steps A2–A4 into `<run>/evening/`).
- [ ] 2 Draft `evening-log.md` from `assets/evening-log.template.md`. It always checks 5 things (Martin 13.10.): 1 roadmap position per client (phase, week, OFF = overdue portal tasks), 2 everything worked through today per client (with link), 3 what is still open (owner), 4 what is NOT delegated (open task with no owner, or owner Martin where the routing table names another doer; else 'only you'), 5 waiting for (who, since). The same 5 checks show in the Command Center tab 'Today' (snapshot field `today`, built by `render_command_center.py`). Then report in chat the same way as Part 1 (`status_report.py --run <run>/evening --mode evening` when a brief.json exists): what got done, what still runs, what got stuck and why, what starts tomorrow (D26).
- [ ] 2b Night queue (D37, Martin's go 13.10.): `python3 ~/.claude/skills/morning-grill/scripts/build_night_queue.py --candidates <run>` lists (0) ready-made `pending_items` other chats offered (state/night-pending.json; offer them on the card unchanged, they still need Martin's tick), (1) the open agent tasks of today and (2) every active client's roadmap step (phase, next milestone, next workflow, blockers) from the goal sheet. Build items from both: an agent task that is night-suitable, or the first night-suitable step toward the client's next milestone when no task covers it (skip steps that wait for a client, a login or a payment). Turn the night-suitable ones (research, draft, public audit, local build; never send, message, publish, deploy, FTP, live writes, ads, money, credit-spending scans, login or Chrome work) into at most 8 items {id (kebab), client, class (draft|research|public_audit|build), lang (German|English), title, brief (what, facts, limits), inputs (repo paths or public URLs), done ('items/<id>/<file>.md ...')}, rank by due date. Ask them as ONE AskUserQuestion card 'Night queue <date>' (multiSelect, recommended items first; more than 4 items = two questions). Write ONLY the ticked items: `build_night_queue.py --write <items.json> --date <today> --confirmed-by "Martin, card 'Night queue <date>' (<what he ticked>)"`. NO ANSWER = NO FILE = no night run. Never write the queue file without his answer; never use --replace unless he says so.
- [ ] 3 One card to Martin: confirm / fix lines / add. Unconfirmed → first item of the next morning brief.
- [ ] 4 Append one line per client to `00_project/assets/morning-grill/logs/<client-slug>.md`. Update `_run.json`.
