# Agent job descriptions

## Critical
- **One description per agent, one file, Martin owns it.** Source of truth: `00_project/agent-jobs/<id>.md`. Placed copies (rules file, scheduled-task header) are generated by `scripts/place.py` and checked by `scripts/validate_jd.py --copies`. Never hand-edit a copy. An agent may propose edits in its review; only Martin's card Go edits the description.
- **Every never-line names its rung** (`hook`, `runner`, `card`, `skill`, `rule`, `advisory`). A never-line without a hook is advisory and the description says so. See `references/rung-ladder.md`.
- **No second approval system.** Two lists per agent: hook-enforced (what `.claude/hooks/live_change_gate.py` blocks) and card-enforced (send, spend, delete, publish, Supabase or portal writes, plus the agent's own items). A Go is one card whose Go option carries the word "Go"; show the exact change first; execute in the same turn (memory `go-gate-hook-needs-typed-go`).
- **The agent never grades itself.** The review draft carries facts and evidence; the A–F grade comes from Martin's card (or a fresh reviewer session that Martin confirms). The template line "do not grade yourself higher to please me" stays in every review.
- **Grep the knowledge base at run time, never copy it here.** `00_project/knowledge/agent-job-library/_derived/agent-job-descriptions-rules.md` (R-numbers cited below), `_derived/agent-job-descriptions-questions.md`, `_derived/roster-2026-11-03.md`.
- English STE in descriptions; client-facing quotes stay German.
- Nothing is placed, written to MEMORY.md, or edited in another agent's files without a card Go for that file.

## Inputs
- Write mode: an agent id or a job name ("Web Developer", "night shift"). A new agent gets its roster entry first (`scripts/roster.py add`).
- Review mode: review week (default: current ISO week) and the active agents from `roster.json`.
- Data folder `00_project/agent-jobs/`: `roster.json`, `roster.md`, `<id>.md`, `reviews/<week>/`, `<id>/inbox/`, `<id>/outbox/`.

## Write mode
1. **Roster.** `python3 .claude/skills/agent-job-descriptions/scripts/roster.py list`. If missing: `roster.py add --id <id> --title "<title>" --type chat|scheduled|runner|backlog --runs-at "<where>"`. Ids are kebab-case and stable (R0.4).
2. **Read the real agent, read-only.** Use the Read tool, not Bash grep, for hook and settings files: the go-gate blocks any Bash command that names `.claude/hooks/` or `.claude/settings.json`. Hook coverage: `references/rung-ladder.md` and `.claude/hooks/README.md`. Scheduled task: `~/.claude/scheduled-tasks/<task>/SKILL.md` and the skill it calls. Runner: its run script and prompts. Chat: its memories, the client roadmap, its skills. New agent: the memories of the area and `references/examples.md`. Never draft from the video vocabulary alone (R1.1).
3. **Grill the gaps.** Only what research cannot answer (`_derived/agent-job-descriptions-questions.md`, section "Open"): who it is, scope, sites or sources, trigger, risk items beyond the house list, done-definition.
4. **Draft** from `references/block-template.md`, all 15 sections in order. Duties = one action, one output, a number where possible (R1.3). Tools rated low/medium/high (R1.6). Never-lines with rung (R1.4). Edge cases include the missing-source rule (R1.8). Link memories instead of copying them.
5. **Validate.** `python3 .claude/skills/agent-job-descriptions/scripts/validate_jd.py 00_project/agent-jobs/<id>.md`, fix, repeat, max 3 rounds. A fourth failure is BLOCKED and reported with the findings. Proceed only at PASS.
6. **Show and ask.** Description plus validator output. One card: "Go, place it (Recommended)" / "Change first". Record Martin's words in the task log.
7. **Place** after the Go, same turn: `python3 .claude/skills/agent-job-descriptions/scripts/place.py --id <id> --rung rules|task` (rules = `.claude/rules/agents/<id>.md` with `paths:` from the roster; task = header block in the scheduled-task SKILL.md between the agent-job markers). Chat agent without path scope: `--rung memory` prints the MEMORY.md pointer line; write it with the Write tool. Then `validate_jd.py --copies <id>`.
8. **Roster and telemetry.** `roster.py set --id <id> status=active`, `roster.py render`; `place.py` wrote `_run.json`. Report file paths, placed copies, which never-lines are advisory only, open proposals. Paste both PASS outputs and the roster.md diff. A description that fails validation is not placed.

## Review mode (Friday, from the morning grill)
1. `python3 .claude/skills/agent-job-descriptions/scripts/collect_evidence.py --id <id> --since <last_review>` per active agent. A missing source is "unreadable", never "nothing happened" (R4.7). A review without an evidence file is not a review.
2. Draft from `references/review-template.md`, no grade. Contradictions found while writing a description (live prompt vs skill) go into the first review's proposals, not into the description.
3. One card per agent: draft in the card text, options "Grade A … F" with the evidence summary; Martin adds one sentence. Max 4 agents per round.
4. For every mistake seen twice this week: one card with the rung decision (memory line / rules file / skill edit / hook proposal). Apply memory, rules and skill fixes after the Go; hook edits only as a proposal for a separate turn.
5. Write `00_project/agent-jobs/reviews/<week>/<id>.md`, `roster.py set --id <id> last_review=<date> last_grade=<A-F>`, `roster.py render`. Report the grades table and applied fixes with paths.
