# Card pattern — how to write a grounded round, not a blank-slate one

Reused from the `morning-grill` skill's card mechanics (AskUserQuestion, max 4 per round, recommended option first, decision recorded before moving on) — not its content. This file is the HOW; `_derived/marketing-grill-questions.md` is the WHAT per round.

## The two shapes a round can take

**Confirmation shape** (use when the read phase already found a real diagnosis, e.g. a recent status check in `revenue-model-100k.md`): state the diagnosis in the question text with its date and source, then ask whether it still holds. Example from the 2026-10-25 hand-run:

> "Your own diagnosis from 21.10. says LinkedIn warm+cold outreach (1 seat) is the active channel, but its funnel broke... Does this match where you actually are?"

This is faster and more honest than re-deriving a from-scratch answer when one already exists — it also gives Martin an explicit chance to say "no, something changed" (always include that as an option).

**Cold-start shape** (use when no recent diagnosis exists, or the round is about a topic the read phase found no state on): present the options generated from the relevant `_derived/marketing-grill-rules.md` section, recommended option first, grounded in why (cite the rule).

## The one hard-won rule: verify before you name

Never put a specific name, number, or state from a memory file directly into a card's question text without either (a) having verified it is current (e.g. checked `team-roster.md` for a team name), or (b) phrasing it as an open check rather than a fact: "per memory file X, dated Y — correct?" This was caught live on 2026-10-25 when a card almost named a team member ("Maya") who is not on the current roster at all. The fix cost a re-ask; the rule now prevents the mistake instead of just correcting it after the fact (per the meta-workflow's "Strict Immediate Skill/Script Patch Rule").
