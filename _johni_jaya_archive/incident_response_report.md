# Security Incident Response Log: Johni Jaya Motor
**Date of Audit:** April 21, 2026
**Target Server:** `johnijayamotor.com`
**Environment Access:** FTP Only (Port 21)

## 1. Description of the Incident
The WordPress installation at `johnijayamotor.com` was subject to a persistent malware reinfection loop.
Even after the site owner attempted manual cleanup (specifically replacing injected code in the active theme's `functions.php`), the malicious code would dynamically regenerate.

The malware payload consisted of:
- **SEO Spam Injections:** Unauthorized links injecting Russian casino advertising (e.g., "pin up казино", "GamStop", "pharma") directly into the front-end DOM and hundreds of hidden ghost posts.
- **Backdoor Authentication Bypass:** A `base64_decode` sequence hooking into the `authenticate` filter, capable of automatically signing an attacker into the WP-Admin dashboard through a hardcoded username/password array.
- **Hidden Botnet Markers:** Numerous 0-byte dotfiles generated by automated malware architectures (like *FilesMan*).

## 2. Methodology & Constraints
Because we only had FTP access (and no SSH/WP-CLI capability), standard incident response scripting was impossible. To solve this, we utilized **Remote PHP Execution** via FTP.

**The Workflow:**
1. A suite of custom, highly-targeted PHP scripts was authored locally.
2. The scripts were uploaded explicitly via FTP (`curl --ftp-ssl -T`).
3. The scripts were executed remotely via standard HTTPS (`curl https://...`), granting us full internal server-side Database and Filesystem interaction capability.
4. Following execution and log output, the temporary tools were set to securely self-destruct (`unlink(__FILE__)`).

## 3. The Execution & Findings

### Phase 1: Environmental Reconnaissance & Deep Audit
- Scanned the root filesystem and immediately identified automated lock files (`.db2_convert`, `.dbx_convert`, `.lock`, `.mb_convert`, `.partition`).
- Noticed modified timestamps on deep core files (`wp-settings.php`), confirming the "Dropper" script (the engine of the reinfection loop) lived in the WordPress core, *not* the theme.
- Identified `.tmb/` subdirectory possessing dangerous `777` global R/W/X permissions.

### Phase 2: Sterilizing the WordPress Core
- Uploaded a custom `restore_core_741.php` orchestrator.
- **Action:** Executed a server-side download of the official `wordpress.zip`, recursively deleted the compromised `wp-includes` and `wp-admin` folders, and overwrote all root `.php` files (neutralizing the dropper in `wp-settings.php`).

### Phase 3: Surgical Database Purge
- Uploaded `clean_db_741.php`.
- **Finding:** Detected a hidden rogue administrator (`adm1n`).
- **Finding:** Executed strict queries against `wp_posts` tracking "casino", "gamstop", "pharma", and "cialis". Detected a staggering **1,556 spam posts**.
- **Action:** Eradicated the rogue administrator from `wp_users` and `wp_usermeta`.
- **Action:** Permanently deleted all 1,556 infected spam instances.
- **Action:** Flushed compromised transient cached options catching `iframe` payload fragments (`_site_transient_wp_plugin_dependencies_plugin_data`).

### Phase 4: Final Hardening & Lockdown
- **Vector Eradication:** Identified `vamtam-importers-e` and Elementor Pro as the extremely likely points of initial exploit (due to known file-upload vulnerabilities). We verified their inactive status and forcibly deleted the Vamtam importer directories permanently.
- **Filesystem Lockdown:** Script recursively swept the filesystem, resetting any loose directories to `755` and files to `644`.
- **Config Lockdown:** Securely injected `define( 'DISALLOW_FILE_EDIT', true );` into `wp-config.php`, terminating the graphical WordPress Theme Editor to prevent immediate backdooring if an admin session is hijacked.

## 4. Final Disposition
- **Result:** The threat is neutralized, the underlying dropper is destroyed, and the SQL payload arrays are deleted. The site is running on a pristine WordPress core.
- **Future Safeguarding:** The site owner must rotate `Dinakar`'s admin password, implement Web Application Firewall (WAF) controls, and critically patch/license Elementor Pro.
